## 1. 对当前研究状态的判断

研究假设已经明确：在同一环境、同一次进程运行中，机器人应利用历史视觉观测与执行经历，
提高后续语言目标的检索和搜寻效率。已有方法表明这条路线具有可行性，但不能因此称本项目
理论已被证明、只剩机械部署。当前两件事须分别完成：目标接近的物理闭环；记忆相对公平基线的收益验证。

现场104335探索近停6.960%，搜索120.038s，行驶103.909m，净位移94.081m，末距目标30.260m，
未到达。它支持本轮探索执行较流畅，不支持完整成功、稳定性统计或视觉记忆提升成功率。

WildOS本身已有图空间记忆。其原文第6-B/6-C节明确指出尚缺图节点视觉特征记忆，
并提出未来增加历史视觉查询。因此研究应表述为扩展历史视觉检索与执行经验，
而不是首次引入图记忆，也不能把作者已写出的未来设想本身当作独创算法。

## 2. 当前系统机制与数据流

### 2.1 环境观测和坐标

- 当前仿真启动链未运行SLAM或真实传感器里程计算法：node.py用模拟器状态位置/姿态经刚体偏置
  转换发布odom；dummy_pose_graph_publisher.py仅发布接口占位单节点，不进行回环或图优化。
  系统仍构建地形/代价地图与导航图，依赖外部可信位姿，不能称无定位依赖或map-free。
  WildOS原文第5-A节使用DLIO提供LiDAR-IMU里程计，并以Elevation Mapping CuPy构建局部高程图。
  DLIO里程计不直接等同含回环和全局一致性优化的完整SLAM。真车需接入并评估定位来源，
  不必指定某种SLAM；长期记忆跨回环修正的空间一致性尚待验证。
- BeamNG输出RGB、相机内参、LiDAR、车体状态；适配器输出测量时间戳、TF和后轴里程计。
- spot1/odom统一节点、目标、轨迹的世界坐标；base_link保留真实高度/俯仰/横滚供传感器使用；
  nav_base_link保留同一后轴XY，Z=0、仅Yaw，供平面车辆规划。三维目标XYZ不被压平成传感器测量。
- 40m点云供地形/障碍处理，80m点云供目标定位。两者用途不同，不能把定位回波直接当成可通行空间。
- 现有地面过滤分离marking与clearing，生成Nav2代价地图；地形网格供GraphNav建图。

### 2.2 感知、frontier与GraphNav

- ExploRFM复用RADIO/NaCLIP及语言对齐特征，产生视觉可通行性、视觉frontier和查询相似度。
- 几何frontier来自已观测地图边界；视觉frontier来自图像。可通行性回答哪里可能走，
  frontier回答哪里值得继续获取信息。它们相互约束，但不是同一个量。
- GraphNav mapper维护稀疏几何图与frontier；WildOS把几何frontier投影进图像，
  根据可通行图像路径、视觉frontier和目标方向，为节点/heading bin赋分。
- 当前BeamNG配置为单前视相机、16个方向bin；类默认支持3相机不等于本轮用了3相机。
- GraphNav planner融合最新拓扑与视觉评分，输出拓扑引导路线；无目标时探索，目标定位后朝该目标规划。

### 2.3 视觉目标如何变成导航目标

- 当前查询文本与语言对齐的空间特征比较，得到掩码；掩码不等于三维目标或已到达。
- 定位器用相机内外参、匹配时间的LiDAR投影及多视几何获得目标位置候选，
  经空间支持、质量判断和多帧共识发布raw_object_waypoint与object_confirmation。
- query不变时坐标细化是同一任务更新；目标XYZ继续服务确认与记忆，导航距离使用XY。
- 已有可信当前目标时优先当前观测，历史检索提示不再作为另一个竞争目标。

### 2.4 四个Store的分工

| 组件 | 实际保存内容 | 何时写入 | 后续作用 |
|---|---|---|---|
| ExecutionExperienceStore | 场景描述子、实际执行方向及结果 | 匹配到执行反馈后 | 相似场景下调整已有方向评分 |
| GraphObservationStore | 既有节点/方向观测、对象证据、搜索覆盖及遍历记录 | 有效观测/确认/反馈 | 组织节点历史和对象查询，提供方向奖励或重复搜索惩罚 |
| ConfirmedViewpointCache | 当前query确认过目标的观察位姿、对象位置和关联证据 | 收到合格确认后 | 再次查询同目标时提供历史观察视点 |
| PassiveLandmarkIndex | 查询无关的空间视觉描述子、LiDAR支持位置、观察位姿和时间 | 行驶中按采样条件被动写入 | 收到后来才提出的query时，在历史区域中检索 |

RecallCandidatePolicy是候选排序规则，不是第五种记忆。VisualMemory/VisualMemoryMap等历史配置名
不等于另有未列出的地图或模块。四种存储职责可在论文中概括为视觉观测、已确认视点和执行经验，
不必包装成四个独立创新。

### 2.5 记忆参与决策的两条链

检索链：历史空间特征 + 新文本query -> 语义相似区域 -> 候选历史视点 -> 候选排序 ->
GraphNav引导 -> Smac规划 -> 回到候选区域重新观察/定位 -> 满足当前视觉证据后到达。
被动索引不需要第一次路过时事先给出“记住加油站”；但成功取决于是否采样到可区分特征和有效空间支持。
索引保存特征，并不自动为每个物体生成可靠自然语言名称；查询匹配或确认后的标签应说明来源。

评分链：当前场景描述子 -> 检索相似执行记录 -> 对齐历史/当前航向 -> 在有执行证据的方向上
调整原始frontier分数 -> GraphNav重新选择路线。它影响偏好，不直接输出方向盘指令或判定障碍可穿越。

代码中的执行先验融合可写为：

    S'(v,h) = clip(S(v,h) * [1 + lambda * (P(h)-1)], 0, 1)

这里S是已有视觉支持，P=1表示没有额外偏好，lambda随检索相似度调整；明确抑制的S保留原值。
这是一条有界启发式融合公式，不是已经证明收敛的强化学习，也不保证全局最优。
历史回报需对应实际执行的方向，未执行方向不应被当成失败样本。

当前RecallCandidatePolicy的实际排序是：

    cost(view) = XY_distance + 2 * abs(bearing_error) + 3 * (1-confidence)

因此目前是距离/转向/置信度启发式，不是完整路径长度或可达概率最优化；真正可执行性仍由Smac检查。
以后论文若使用d_G或成功概率等新目标，必须标注为新设计并实现验证，不能把当前欧氏启发式写成它们。

### 2.6 连续规划、执行与到达

- GraphPathBridge只协调当前任务、候选和标准Nav2 Action，不生成另一套全局几何地图。
- ComputePathToPose调用Smac生成符合车辆曲率/轮廓约束的路径，RPP跟踪并检查局部预测碰撞。
  Smac在Nav2被称为全局规划插件，在整个分层系统中负责拓扑引导之后的车辆几何路径。
- 新规划在后台执行；未成功时保留当前健康FollowPath，成功后标准抢占。
- RPP速度/角速度 -> CmdVelToControl速度闭环、转角与换挡 -> NativeVehicleControl直连车辆。
- 完成条件为后轴与当前目标XY<3m，同时具备当前query的新鲜视觉确认；当前实现还核对
  确认位置与目标/车辆的XY一致性。历史坐标本身不能证明到达。
- 里程计进展与执行结果写回现有存储，形成观测—决策—执行—经验闭环。

### 2.7 存储与证据边界

当前实现的逐接口类型、字段、张量形状、存储格式及时间语义见同目录DATA_FLOW_CONTRACTS.md。
该字典按实际源码编写，不将数据类型定义的可选能力冒充已上线的完整测量或反馈。

同一进程跨query保留，不要求跨进程。复用已有几何图不等于map-free：仍有地形图、代价地图和稀疏语义索引。
PassiveLandmarkIndex默认最多1024槽位、数组预算8MiB，特征用float16；8MiB不是所有Store、
SQLite索引、视觉网络及整个进程的内存总量。GraphObservationStore总量随图/对象观测增长，
必须测量全部Store及RSS后，才能声称总体内存有界或优于其他方法。
ExecutionExperienceStore支持不同结果标签，但当前桥接反馈明确发布了成功进展；
失败/碰撞标签是否完整进入在线反馈链仍须专项核验，不能声称已验证“从全部失败中学习”。

## 3. 论文问题定义与潜在贡献

任务：在未知环境连续执行语言目标序列q_1...q_K；任务切换保留环境经历，
不预告后续查询，不要求回溯原路径。给定RGB、LiDAR和里程计，利用原有图G_t与历史存储M_t选择行动。
可写成部分可观测的序列导航问题，策略pi(a_t | o_t, q_k, G_t, M_t)。
这是问题形式化，不代表当前启发式代码实现了完整贝叶斯POMDP求解器。

核心研究问题：历史信息能否在不建立第二套稠密语义地图、不重训基础视觉模型的条件下，
降低后续目标的探索距离、耗时和重复访问，同时维持车辆执行成功率？

建议围绕两个方法贡献和一个实验贡献组织，而非新增运行模块：

1. 查询无关的稀疏观测保留与查询后的回顾检索：把位置、视点和语言对齐特征关联，
   使未事先指定的后续目标能利用历史观测。表示稀疏性和相对已有工作优势须实测。
2. 检索提示、当前确认与执行经验的分工：历史记忆影响候选区域和已有方向评分，
   当前感知负责目标确认，现有规划器负责可达性；用实际执行经验校正语义偏好。
3. 拟在真实机器人上按同一环境连续查询，评估记忆收益、误召回和资源代价，
   仿真用于可复现消融与预验证。真车证据目前缺失，仍是待实施的验证贡献，
   不把仿真迁移、ROS消息转换、bug修复或Smac/RPP组合本身当新算法。

上述是待检验的贡献定位，不是全球首次声明。WildOS已提议视觉记忆扩展；GOAT、Tag Map和OVAL
与本课题有明显交叉，必须比较具体表示、反馈作用、存储成本及任务设定。

## 5. 论文框架

暂定中文题目：面向连续开放词汇目标导航的轻量视觉记忆与执行经验融合。
暂定英文题目：Lightweight Visual Recall and Execution Experience for Sequential Open-Vocabulary Navigation。
机器人运动学由具体执行后端处理；BeamNG仅写在仿真设置中。
方法不应以某款车的偏置、转向符号、模拟器接口或话题名为定义，
但方法与接口可分离不等于已经验证跨平台泛化。

### 摘要提纲（结果尚空缺）

开放词汇导航需要机器人在连续目标之间复用既往经历。我们研究在已有拓扑导航系统上，
利用稀疏视觉观测与执行经验支持后来提出的查询。方法复用预训练视觉语言特征与既有导航图，
以历史区域和视点提供搜寻先验，以执行反馈调整方向偏好，并以当前视觉观测完成确认。
我们计划在真实机器人上进行冷启动与连续查询对照，并通过仿真补充消融和内存预算评测。
真车实验尚未开展或数据不足，待完成后再改为已完成时态。
此处补入实际成功率、耗时/路程变化、存储/检索开销及统计区间；未取得前不写优于基线的结论。

### 1 Introduction

问题动机：经过某物体后才收到相关query，若没有可查询的历史视觉，容易重复探索。
区分已有拓扑探索历史和可追溯的视觉语义经历；提出研究问题和2+1贡献，明确继承WildOS的部分。

### 2 Related Work

2.1 开放词汇目标导航与语义frontier；2.2 视觉语言空间表示；
2.3 连续目标/长期记忆导航；2.4 执行经验与可达性反馈。
以表示粒度、query是否预知、是否复用历史、是否含执行反馈、内存与传感器需求建立比较表，
对未在论文中查实的功能用“未明确报告”，不武断填否。

### 3 Problem Formulation

定义query序列、传感器观测、图、历史记录、记忆保留范围、运动学与时间预算、成功条件。
将首次搜寻与曾见目标召回分开；事先给定目标的预记忆和事后才查询的被动记忆分开。
同一个多目标序列中每个query都有相同预算；初始地图加载与模型启动单独统计。

### 4 Method

4.1 WildOS baseline与分层数据流（压缩说明，明确引用）；
4.2 稀疏历史观测表示及更新/去重/容量；
4.3 开放词汇回顾检索与历史视点排序；
4.4 场景—方向执行先验与有界评分融合；
4.5 当前目标细化、标准规划交接与视觉到达；
4.6 存储/查询复杂度及部署边界。
当前欧氏候选排序、启发式回报等必须如实写出；未实现的新公式不得充作运行算法。

### 5 Experimental Setup

5.1 真实机器人平台与传感器、定位、规划执行后端；5.2 真车连续目标任务与独立标注；
5.3 基线与消融；5.4 仿真补充设置；5.5 资源与统计口径。
固定基础模型、图/代价地图、点云过滤、规划控制器、车辆尺寸、速度、起点和目标序列。
公平主基线是同一已修执行栈、关闭新增记忆；原始上游系统单列，不能用其不同执行条件混淆记忆收益。
选择多个起点、多个目标和查询顺序，包含未见目标、被动见过但未查过、查找过的已确认目标、
多实例/外观混淆、记忆不足或不匹配，以及临时路径受阻。

### 6 Results

6.1 真车目标级与序列级成功率；6.2 首次/后续query的时间和路程；
6.3 真车轨迹与误召回案例；6.4 消融（真车/仿真分别标注）；
6.5 内存与检索延时；6.6 失败分解与感知/执行误差影响。
当前结果只能填已观测事实，完整成功和记忆收益未取得，不补造结果。

### 7 Discussion and Limitations

误检可能污染记忆，视觉相似不等于同一物体或同样可达；动态环境和定位漂移会使历史失效；
当前仅同进程，未证明跨进程、跨地图或真车迁移；全局内存增长尚待统计；
query为颜色/属性组合时仍受基础模型能力限制。地图/传感器闭环故障与记忆决策错误分开分析。

### 8 Conclusion

只归纳数据支持的贡献，讨论物理闭环与记忆方法可迁移的边界，不以单个成功视频支撑普遍结论。

|---|---|---|
| B0：记忆关闭 | 相同感知、图、接近、Smac/RPP与车体 | 公平WildOS执行基线 |
| B1：仅历史坐标/已确认视点 | 不启用被动特征回查 | 收益是否仅来自缓存位置 |
| B2：视觉回顾检索 | 关闭执行经验对评分的作用 | 视觉历史本身的贡献 |
| B3：B2+执行经验 | 其他条件与B2一致 | 反馈是否进一步改善路线 |
| B4：完整方案减去查询无关采样 | 后来才提及的目标无法提前采样 | 是否真的不需要事先指定记忆对象 |

一个地图只加载一次，连续下发q1→q2→q3，不清除合法的跨query历史。各方法使用相同序列与随机种子。
为单独测召回，可提供相同传感器历史给各方法再开始测量；这与全流程在线序列试验分别报告。
不得注入真实目标坐标给被测方法；地面真值只用于独立评价。冷启动目标、历史可见目标分层统计。
失败轮次计入分母，报告所有轮次、配对差异及区间，预先决定样本量，不因结果好坏选择录像或停止采样。

主指标：独立语义正确的SR、序列成功率、搜索耗时、路径长度、重复探索量、历史检索准确率/覆盖率。
SPL需要面向真实车辆约束和同一目标可达区域的最短参考路径；直线距离不能冒称最短可行路线。
另报首次2D可见、首次3D定位、首次可执行接近、到达四个时间点，以及collision/no-path恢复损失。
内存报告分Store与总RSS增量；延时报检索P50/P95及视觉/规划开销。近停率作为执行回归约束保留，
不继续作为本论文主要创新或优化主目标。当前BeamNG的120秒/3米标准不自动作为通用任务定义；
真车预算、语义正确性和到达区域须事先确定，对所有对照统一执行，不能见结果后调整。
