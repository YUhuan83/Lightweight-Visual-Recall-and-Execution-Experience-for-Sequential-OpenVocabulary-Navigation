# Town 同进程视觉记忆返航测试（2026-09-27）

## 实现

修改 [nav.py](C:/Users/Yu/Desktop/拟真/wildos_port/repro_check/src/nebula2-wildos/visual_navigation/visual_navigation/wildos/nav.py)：

- 支持通过 `/spot1/object_search/query` 在同一个 WildOS 节点中切换目标，并预缓存“gas station”和“trash can”的文本特征。
- 最近一帧空间视觉特征仅在 1 秒内、位姿变化不超过 0.2 米和 8°时复用。
- 将检测得到的 `/spot1/imgnav_waypoint` 按当前查询词缓存在进程内；切回已记忆的目标时，重发接近位姿给 graphnav planner。
- 两个视觉记忆 SQLite 路径均设为 `:memory:`，不跨进程保存。

## 测试结果

- BeamNG Town 地图进程保持同一 PID `1448973`；WildOS 在目标切换期间保持同一 PID `1580487`。
- 从出生点的“gas station”掩码和 LiDAR 投影得到接近位姿，WildOS 记录在当前进程内存。

- 第一轮 graphnav 路径含 4 个姿态点，终点 `(714.39, -16.45)`；第二轮终点 `(715.53, -16.46)`。端点差异来自同一静止视角中 LiDAR 接近点的更新。
- `nav.py` 本地及服务器端 `py_compile` 均通过。

**结论：已在真实 ROS/BeamNG 会话中验证记忆目标优先于 frontier 目标；车辆实际搜寻后自主返站仍未验证成功。**

## 需求澄清（2026-09-28）

目标是再次搜寻曾见过的物体时，立即复用同一进程内的物体位置和已加载地图，从车辆当前位置快速计算可行路线，避免重新进行 frontier 搜寻。无需沿先前行驶轨迹原路返回。Town 日志显示记忆目标到 Nav2 路径生成通常只需约 5–6 毫秒；这证明了目标调用和路径计算的速度，尚不能证明路径可驾驶或车辆已到达。重新从当前位置计算几何路径仍是必要的，因为当前位置和障碍状态可能已变化。

为提高路线可驾驶性，记忆目标现选用 Nav2 `SmacPlannerHybrid` 的前进档 Dubin 运动模型，最小转弯半径设为 10 米，与控制适配器默认 0.5 的归一化转向上限、3 米轴距和 0.6 弧度最大转角约束一致；frontier 中间目标继续使用原 `NavfnPlanner`。两个代价地图的碰撞范围从半径 1.2 米的圆改为约 4.6×2.0 米的车辆矩形。服务器构建成功，适配器 29 项测试通过；静态位姿的 `CarLike` 规划检查返回 169 个路径姿态点，规划耗时约 0.059 秒。新配置尚未在 BeamNG 中完成驾驶验证，上一轮游戏崩溃后已停止。
