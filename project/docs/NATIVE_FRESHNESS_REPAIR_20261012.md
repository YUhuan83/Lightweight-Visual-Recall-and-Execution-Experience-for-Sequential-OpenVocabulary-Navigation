# 2026-10-12 Native 控制时间契约修复

## 已确认的问题

`NativeVehicleControl → /wildos/native_control_status → CmdVelToControl`
之间存在可以独立复现的新鲜度错误：

1. 状态轮询返回后用接收时间重置样本年龄，慢轮询得到的数据又被赋予新的 StateSensor 时间戳。
2. 控制 RPC 前计算遥测年龄，RPC 后发布新的 wall_time；因此一次慢 ACK 会把已经过期的状态报为新鲜。
3. 速度环分别要求传输年龄和采样年龄不超过 .5 秒，没有累加；接收后又给消息完整的 .5 秒有效期。重复消息也可能让旧状态继续有效。
4. 原 `sent` 只表示拟发送输入，没有逐次 ACK 标志；失败后继续发布制动意图不能证明制动已执行。执行状态还缺 `target_angular`。

新增四个核心反例在原代码上全部失败，日志见
`test_artifacts/offline_navigation/native_freshness_before_20261012.log`。
这些错误已确定存在，但**尚未证明它们造成 pilot5 的引擎整体响应空档**。

## 修改与影响

- native 以轮询请求开始时间保守计龄；超过已有 .5 秒保护的样本不再发布新的 StateSensor。
- 控制 RPC 返回后，按同一缓存样本重新计算状态年龄和命令年龄。并发新轮询的样本属于下一条状态记录，不替换当前记录的时间身份。
- 速度环累加采样年龄、传输年龄、接收后的稳态经过时间；旧消息不能重新取得完整有效期。显式未 ACK 的控制记录不能用于启用。
- 增加 `control_acknowledged`、`control_rpc_ms`、`poll_roundtrip_ms`、当前样本年龄与 `target_angular`。ACK 只证明 BeamNG 接收输入，实际运动仍需独立核验。
- 保留 .5/.8/2 秒已有保护、执行故障锁定、换挡和速度策略。修复影响失效制动判断，不能提高引擎计算速度或自动消除路径偏离。
- 更正注释：独立 TCP 流可以复用同一车辆监听端口，也仍然共享引擎/渲染回调；不能把独立控制连接描述成完全隔离。
