## 数据流与状态约定

1. **选择与持有。** 新 `ExplorationTarget` 保存 UUID、固定目标位置、选定观察朝向，以及“进程实例标识＋序号”的交易身份。评分变化或 mapper 删去 frontier UUID 不会静默抢占已提交目标；保持目的地，继续利用新图更新路线。位置距离优先使用同 frame、源龄不超过 0.5 秒的实际 odom，缺席时选点距离仍可回退图节点，但不能由此完成观察。
2. **配套路线元数据。** `route_status` 带 `exploration_id`、`endpoint_observed`；Bridge 的执行状态带相同 ID 和真正的 `exploration_goal`。原路径头戳仍标识一次路线发布，不再承担整个目标交易的身份。
3. **实际终点交接。** 完整探索路线的局部规划延伸到元数据中的真正目标，而非停在图连接半径内的图路径末点；不完整 frontier prefix 不跨越未知尾段。对象/记忆目的地仍有优先权。碰撞、曲率和实际姿态检查保持。
4. **观察回传。** Bridge 只有在实际目标 1 米内、选定朝向误差不超过 0.35 rad、平面速度不超过 0.15 m/s、输入新鲜、没有活动/待定动作时，才向 `observed_route_endpoint` 回传已发布路线的原 header/末点。它优先使用同一交易的最新路线，保证长动作之后仍有新鲜的可关联消息；不会借用新目标的路线身份。
5. **观察完成。** GraphNav 先校验回传与已发布路线的精确关联、交易归属，再要求真实 odom 在同 frame、源龄不超过 0.5 秒、单位四元数有效、实际目标 1 米内，并满足原 1.5 秒采集时间的低速/朝向观察条件。没有 odom、旧 odom、暂停不推进采集戳、没有回传，都不能完成观察。完成才增加 visits；图规划空路径不再算完成访问。
6. **失败与退役。** 局部拒绝必须关联当前交易；迟到的旧目标拒绝不能清除新目标。图规划失败使用原临时退避，不写作成功观察。完成观察、图规划失败、有效拒绝、frame 切换或目标复位均发布带交易 ID/时间/原因的 `retired_exploration`。
7. **执行端撤销与乱序。** Bridge 只撤销匹配的探索交易，复用现有 reset、动作取消、隔离与 execution hold；不把清空 following 当作控制器已停。保留至多 64 个退役 ID，拒绝之后迟到的该目标路径；先退役、后元数据/路径也不能复活动作。旧/未来/过期/上一 query 的退役消息被拒绝，别的交易与对象目的地不受其取消。

观测距离的 1 米是探索终点交接约束；对象到达、视觉定位/确认与记忆重观察标准没有放宽。没有关闭车体/轮胎碰撞，没有更改速度或转弯半径，没有把加油站列入黑名单。
