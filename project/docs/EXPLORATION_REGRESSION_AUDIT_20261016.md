## 1. 已在本轮证明的主要问题：局部失败被扩大为探索区域屏蔽

### 最早违反的语义约定

`GraphPathBridge.reject_exploration_route` 发的是 PoseStamped：只有相关路线与终点，没有失败原因、发生的运动段、障碍单元、地图版本或证据置信度。

C++ `ExplorationBackoff.reject` 统一解释成：

1. 探索目标中心 **12 米**内的候选屏蔽 **120 秒**。
2. 车辆位置距已下发图路某段不超过 **6 米**时，再屏蔽失败位置中心 **8 米**内候选。
3. 暂时屏蔽该最近图边，时间也是 120 秒。

但“当前车姿下，一组朝向或短前缀未找到车辆路径”只证明本次尝试失败，不证明远处目标及其邻域都不可探索。一次局部 footprint 拒绝也没有定位整条图边的障碍。原始 PoseStamped 接口把这些区别丢失了。

本轮接受的 21 次拒绝分别对应 12 次 no_vehicle_path、7 次重复 local_footprint_collision、2 次 no_free_graph_candidate。目标距失败位置约 16.84～71.81 米；6 次目标和被拒路线端点还相隔超过 10 米。失败前缀和最终探索目标的证据范围显然不同。

### 同一批真实图上的结果

下表时间以 **bag 接收到 query 为零点**，不能直接作为 MP4 的 seek 秒数。

| 抽样时刻 | 原始 frontier 数 | 基本筛选后候选 | 区域退避屏蔽 | 原有完整图路候选 | 区域与图边退避后剩余完整图路候选 |
|---|---:|---:|---:|---:|---:|
| 240.410 秒 | 60 | 51 | 51 | 28 | 0 |
| 418.288 秒 | 60 | 56 | 56 | 29 | 0 |

62 份抽样中，13 份出现基本筛选后的候选全部被区域退避排除。**图路完整不代表真实汽车一定可执行**，但它证实不是上游没有 frontier，而是新增策略把它们排除了。

实际 route_status/path 从 239.727 到 312.354 秒有 **72.627 秒发布空档**；这期间仍有 scored graph 和 frontier。第一条退避在 311.905 秒到期，之后约 0.449 秒再次有选点输出。这与退避耗尽候选、等过期恢复的机制一致。

`choose_exploration_goal` 无候选时返回 nullopt，`plan_to_goal` 随即直接 return，没有发布“候选耗尽”的明确状态、最近到期时间或恢复请求。于是外部看到车辆静止，原有恢复又不能从这个状态直接接管。

**修正排查方向：** 本轮图边屏蔽虽然改变部分路线，但回放中没有把原本完整的候选图路断开；主要证据是候选区域过滤清空。不得把早期怀疑的“图边切断唯一出口”当成本轮已证事实。

## 2. 探索策略已被改写，不能再称完整原生流程未变

| 层 | 原版固定源码 | 当前增加的行为及影响 |
|---|---|---|
| 探索目的地 | PlannerNode 接收外部 goal；Planner 将目标、frontier 代价和已有图路一起作 Dijkstra 比较 | 新增 `choose_exploration_goal`，先按最大 heading 效用、物理置信度、距离和 UUID visits 选择目的地 |
| 方向 | frontier_scores 按目标方向读取 bin | 新增转向代价、置信度、覆盖与记忆项，再用 `HeadingCandidate.traversable` 作整节点淘汰条件 |
| 已知图路 | 在同一个扩展图中比较 | 新增完整已知图路优先返回分支；本轮 748 份决策中 644 份为 complete，不能把这些全部当成原版 frontier 成本竞争结果 |
| 执行与观察 | 原图路／path follower 接口 | 新增真实汽车 Smac／RPP、固定观察 heading、目标保持与观察 ACK；防目标偷换的归属保护已有价值，但严格车姿的实际代价必须进入选点 |
| 失败 | 原版没有该车辆拒绝闭环 | 新增 12m／8m／120s 区域退避及图边屏蔽；本轮已证明候选耗尽 |
| 车辆成本 | 原代码不提供该汽车成本接口 | 新增最多查看前 8 项、24m 内最多 4 项的只读比较；限制的是比较集合，并非只允许探索 24m。无法抵消后续全区域排除 |

WildOS 模型和评分仍在工作，本轮记录 967 次评分；不能说它完全没有运行。但我新增的选点、方向和失败策略已经改变“去哪儿、何时放弃、何时继续”的决策。只关闭记忆检索并不能恢复原版行为。

不能盲目删除已验证的事务身份、目标握手、动作隔离、坐标与时间戳保护；修复应针对证据范围错误和候选耗尽交接。

## 3. 已复现但本轮尚未证明触发的探索缺陷

### heading 未知状态被当成不可通行

`nav.py:_append_heading_candidates` 要求 assessment 存在、feasible、physical>0、dynamic<1，才能标记 traversable；没有检查该否定是否具有足够置信度和新鲜度。下游 C++ 却只把新鲜且 confidence>=0.7 的否定视为硬阻塞。两端约定冲突。

直接执行当前 Python 方法体，低置信度否定、过期否定和缺失 assessment 都能生成 16 个不可通行方向，随后选点器淘汰整个 frontier。有效观测和新鲜高置信度阻塞的对照也保留。

**本轮 62 份抽样、3521 个 frontier 节点帧中，此类额外 veto 为 0。** 因而这是当前代码潜在故障，不是本轮 72 秒空档的已证原因。

### GraphObservationStore 的方向与节点关联缺口

当前仍将 heading_mask 做 OR，却只保存一个 negative_evidence=max。反例中方向 0 写入 1.0、方向 8 写入 0.1，方向 8 读取后也承受 1.0。相同区域换 UUID 时又不继承原覆盖；两种情况分别可能错罚未充分观察方向、或重复奖励已观察区域。

`1-max(raw_similarity)` 仍不能当作校准后的“不存在概率”。这些是先前审计已记录、目前仍未解决的缺口；没有封存本轮私有 DB 的逐行历史，不把它们强行归为某个现场节点的原因。

### ExecutionExperienceStore 的失败生产链缺席

消费端支持失败结果，Bridge `finish_execution_feedback` 却把 succeeded 设为学习 eligibility 必要条件，只发成功标签。当前直接方法反例仍显示实际运动后失败 learning_eligible=false。本轮 7 次写入／840 次检索命中、memory_modified_scores=0，不能声称已学会避免失败路线。

这属于闭环没有实现完整，不足以证明它主动将车辆引向错误区域。本轮没有目标 mask、定位、确认或非空召回目标，亦无“记忆把 green house 偷换成加油站”的证据。

- 本轮没有证明 ROS2 或 BeamNG 引擎异常导致上述 72 秒空档；不据此排除所有时序与仿真风险。

## 5. 后续修复顺序及回归边界

1. **先区分尝试失败和区域不可达。** 带明确原因和证据范围的反馈；路径／朝向／车姿／地图版本对应的尝试退避不能自动变成远处 frontier 邻域禁用。局部地图中可信障碍才能更新相应几何约束。
2. **补候选耗尽出口。** 发布明确状态与到期时间，保留连接性；在安全条件下由统一恢复状态机处理当前位置受困，不能只等 120 秒或换另一个远处目标继续同点失败。门禁逐项记录，不放宽碰撞或不确定动作保护。
3. **统一 heading 三态契约。** 已证可行、已证阻塞、未知；未知降低收益但保留探索。跨 profile、TTL、缺失和乱序观测一致处理。
4. **修搜索覆盖及经验类别。** 按方向保存证据与时间，严格关联节点更替；搜索无目标、几何阻塞、控制异常、用户停止分别处理，不混训成地形标签。
5. **建立受控对照。** 固定同一车辆、地图、传感器、适配器及可执行目标协议，先让不含新增记忆先验的探索基线正常扩展，再只开启记忆增量比较。当前生产还包含多种自定义策略，不能以开关记忆命名为完整原版对照。

至少保留“本车姿／本朝向无解，但另一 frontier 的图路线仍存在”“所有候选同时退避”“退避到期”“局部动态碰撞”“缺失／过期／低置信度 assessment”“旧拒绝／query 切换”等反例，再验证完整实际车辆流程。单次路径、回调通过和本次审计复现不计入 20 轮成功数。
