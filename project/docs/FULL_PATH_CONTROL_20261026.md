## 当前机制

WildOS 图路线/视觉评分 → Smac 生成车辆可执行整路 → 一个 FollowPath 动作连续跟踪整路。前向新路径可在旧动作运行时准备并替换；新计算失败不取消健康动作。

v24 仍由 Bridge 按方向拆多个动作；v37 不再将换向点变成多个 FollowPath。控制器内部维护方向与进度，仅在真正前进/倒车切换处先发新鲜制动，实际平面速度与角速度均不超过 0.05 后再换向。换向位置/航向沿用 0.2m/0.35rad。普通路径点不产生动作终态。

RPP 最近点裁剪只看到当前方向的路径，不能跳到重叠倒行/后续支路。进度门在前面方向尚未执行完时阻止最终 GoalChecker 成功，避免最终点恰在车旁导致提前结束。仅对真实停稳后已经满足最终位姿的短末尾作完成处理，之前的实质运动不省略。

`/wildos/controller_path_progress` 回传当前方向的剩余路径：Path.header 时间戳绑定接纳路径，各 Pose 时间戳表示新进度计算。Bridge 核对活动动作、路径身份及 0.5s 新鲜度，不跨动作复用，也不从整路的任意最近点猜测已通过哪个 cusp。

同 query 的 frontier 退休复用原有有界交接（16m/15s），后台接替；目标切换、停止、碰撞、跟踪偏离、输入或执行源失效仍走原取消/停车/ACK。保持 12m 名义规划、8m 实际控制半径，非零命令在碰撞预测前限制曲率到 1/8，禁止原地旋转。真实车体/轮胎、地图障碍、新鲜度、命令租约、可靠定位和车身外缘 2m 最终到达不变。视觉记忆存储、评分及三维定位源码未改。

原论文没有提供当前完整真实汽车控制器。原 follower 发布前视 Pose，仍不是本候选车辆曲线的直接输入；v37 采用持续路径跟随原则并保留真实汽车的可行曲线和换向处理，不能称为原论文所有执行实现的原样恢复。
