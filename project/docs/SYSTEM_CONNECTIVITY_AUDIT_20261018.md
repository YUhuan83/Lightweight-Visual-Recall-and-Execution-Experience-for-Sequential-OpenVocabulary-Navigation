## 3. 三处会破坏任务闭环的机制

### 3.1 同查询内成功重置也耗尽预算，阻断后续图路

`visible_approach.py::release_visible_approach`直接设query_reset_pending/inflight，绕过`navigation_transactions.py::request_graph_reset`。初始清理及两次释放均成功，下一次释放仍继承attempts=3，拒绝派发，pending=true/waiting为空。新增探针进一步将新鲜GraphNav路线送入实际`on_route`，确认以query_reset_pending拒收，证明影响跨到路径入口。

这是逻辑等待无法自行解除，**并非已证明线程互锁**。不能把response_budget_exhausted解释为三次真实服务超时。待修复：统一新事务入口，同时保存旧clear排空、迟到/重复/异常响应隔离和单次真实失败的上限。

### 3.2 同一个清目标服务还会清除探索退避

`graphnav_planner/src/planner_node.cpp`的clear_goal同时清explicit goal、退役探索目标、`exploration_backoff_.clear()`并重建planner图；`ExplorationBackoff.clear`同时删除路由身份和失败尝试。Bridge在同query内临时靠近释放、frontier选择ACK超时等也使用这个服务。

因此“恢复探索的同步屏障”具有“忘掉此前探索拒绝”的副作用。**这是当前源码契约事实，尚未逐次证明上轮某次重选由此引起。** 设计修复需区分新query/map、撤销explicit目标和同query恢复；不能简单永久保留所有退避，也不能只重置Python计数后忽略C++副作用。

### 3.3 局部动作成功不保证探索推进，反馈不能充分纠正

- 当前实际方法重放同探索事务20次往返，局部都成功，recovery_attempts=0且没有探索拒绝；重复的距离改善不会重复记账，但还缺成功循环的任务级退出。外层420秒测试预算仍会结束，不能描述为整个程序无限运行。
- 当前生产经验采样heading_scores=None，执行反馈发布者仅产生SUCCEEDED，消费端reward=1；新鲜ExecutionExperienceStore检索全1。乘法融合不会改变分数。这只说明此条当前监督链无增量，不能泛化为四组件均无用。不得为打破全1而把传输或未知失败写成地形失败。
- GraphObservationStore将不同方向的negative_evidence保存为节点级最大值。当前反例方向0强度1、方向8强度0.1，合并后强度仍1、heading_mask=257，缺少方向独立质量。不是仅改检索阈值能解决的问题。
- 被持有frontier持续从图中缺失仍无有界策略；缺失允许暂时容忍有理由，但须与真实观察收益、任务进展和重选条件共同定义，不能恢复每次UUID消失即取消底盘的旧行为。

**上轮新增记忆先验关闭**；当前同窗口retrieve_calls=0、memory utility delta=0是基线条件，不能用这些记忆缺陷解释该轮停车。它们是后续实现完整记忆实验前必须处理的独立问题。

## 5. 处理顺序及共同验收边界

1. **统一任务与事务归属**：query/map epoch、探索/显式目标、planner请求、已接受FollowPath、clear意图各自有身份和权限；先解决重复清理、同query服务副作用和等待出口。覆盖正常、超时、异常、重复、乱序、目标切换及旧响应排空。
2. **统一可走空间**：对齐语义可通行、已观测自由/未知、障碍与车体扫掠的空间和时间。先封闭地图/点云/路径片段复现，明确哪些是软代价、哪些是硬障碍，避免所有未知禁行或把低分区一律变墙。
3. **统一规划与执行的动态条件**：固定原真实车体测量转角、正反向、单段停车、短段及换向包络；路径选择纳入首段接入、实际速度、制动/换挡成本，移动接替经过受控片段验收。不能仅加长租约或放开多段替换。
4. **补齐任务推进与经验监督**：定义新观察/覆盖/可达进展与有界重选，按方向与观测质量记录；传输失效、动态障碍和未知失败不作静态地形惩罚。先共同执行链，再开记忆做同图对照。
5. **独立捕获Native迟滞故障边界**：保持Smac已修版本，故障帧配内核、recv、DDS、ready、callback及源期限。当前证据不足以指定中间件修复；捕获并组件验证后再合并Native候选。
6. **最后整车闭环验收**：每次冻结唯一身份，检查服务器残留，按真实视觉到达、实际轨迹、长停原因、有效探索/观察和停止清理共同判定。20轮16次门槛及后续多目标仍未开始满足。

本轮已把“为什么经常停”收窄为明确逻辑阻塞、频繁分段/换挡和规划等待、少量实车有驱动无进展三类。底层动态标定、私有地图真值和间歇Native时序仍缺必要证据，不能宣称全部根因已穷尽或整体已经修好。
