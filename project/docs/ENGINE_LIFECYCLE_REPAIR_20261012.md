## 修复与接口约定

仅修改本项目 `tools/attach_current_vehicle_sensors.py`，未修改原生产 Git 树或 BeamNG 二进制。

- 必须传入 `--engine-pid` 和本机监听地址，在 SDK 接入前核对 BeamNG 命令及端口。
- Linux pidfd 固定进程实例；PID或端口复用不能延长旧桥的所有权。主循环每0.2s检查，无额外 SDK 心跳负载。
- 该进程全部 `Connection.send` 在发送前检查同一引擎身份，包括轮询、重连和删除。旧引擎退出后，不允许清理请求污染新实例；现有失败关闭的分帧读取继续保留。
- pidfd 的 `poll()` 和关闭用短锁保护；锁不覆盖 SDK 网络调用，避免把 GE/VE 通信串行化。
- 使用 `SignalHandlerOptions.NO` 保留自定义停止请求，先停执行器/轮询、移除拥有的传感器、清理桥，再关闭 ROS 上下文。
- 地图、车辆物理、车身/轮胎碰撞、8m规划半径、路径保护、速度参数未改。桥退出不代表已清除其他进程的视觉记忆。

该工具当前需要支持 pidfd 的 Linux/Python，缺失时在接入前失败。远程 BeamNG 地址不支持本机 PID 所有权约定，明确拒绝。调用方需更新 CLI 参数；传感器检查脚本可直接部署，不必重建 ROS 插件。
