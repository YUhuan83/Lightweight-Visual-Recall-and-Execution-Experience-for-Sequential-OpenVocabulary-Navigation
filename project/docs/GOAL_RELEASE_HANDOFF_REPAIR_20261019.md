## 两端实现

| 入口 | 行为与约束 |
| --- | --- |
| C++ `clear_goal` | 保留原完整目标/失败暂缓清理语义，供新查询；不清地图或实测已探索区域 |
| C++新增 `release_goal` | 释放目标、退役当前探索身份及候选报价，保留位置相关、120秒有效的失败暂缓 |
| 显式 `goal_pose` | 不再无条件清失败暂缓；新查询由完整清理屏障负责 |
| Bridge `request_graph_reset(reset_search=True)` | on_query专用；未完成的完整清理不能被同查询释放或确认fence变化降级 |
| Bridge默认清理请求 | 视觉/召回/观测/比较失败等同查询交接使用release_goal；记录操作类型 |
| 两种异步服务 | 共享未决请求排空屏障；提升为完整清理时新serial接管；旧响应只排空旧请求，不能冒充新意图成功 |

共审查9处调用，只有on_query显式申请完整清理；明细 `call_sites.json`。原三次预算、实例释放确认、旧响应隔离及停车保护保持。两类服务分别缺失时不回退为另一种语义。

`server_test_preflight.py`新增两个Trigger服务的类型/存在检查，旧Planner没有release_goal会在测试门禁失败。测试夹具为既有状态测试提供两个注入端口；8项新增用例使用独立服务替身验证选路、提升、不可降级、确认fence改变、乱序成功/失败与缺失服务。

## C++目标时间边界

新增 `destination_fence.hpp`：两种清理都记录当前ROS时间；接受目标必须严格晚于清理时间、晚于上次已接受目标，且不超出当前ROS时间。重复、清理前、乱序、未来或非法stamp不能更新已接受时间。Bridge原有relay_destination仍在清理屏障完成后用自身ROS时钟重新打戳。

此处没有比较Python monotonic或BeamNG sim秒，单位统一为ROS纳秒。相同清理时间戳的目标保守拒绝；正常目标在时钟推进及ACK后发布。35项C++含6个新边界回归，实际DDS同时验证“拒旧”及“仍可接收新目标”。

**限制**：依赖两端一致、连续的ROS时钟；纯时间边界不等价于端到端query/动作UUID。时钟大回退时能拒旧未来戳，但不能宣称覆盖任意跨epoch重合；实际传感器重启及完整任务身份协议仍开放。正式现场前须再核两端时钟模式及运行来源。不要因接口通过而放松其它新鲜度门槛。
