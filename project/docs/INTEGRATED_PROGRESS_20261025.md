- `official_graph_stack.launch.py`：历史支持保留60秒；最新观测≤5秒、四条支持、实例和2米最终到达不变。

未修改本轮Smac/RPP/物理/速度/地图/控制参数。主目录用户源码不覆盖，v28–v32及原归档全部保留。

### 轨迹和停顿原因，两遍复核

`audit_latest_displacement.py`只读本机已关闭的Native/events，独立复算并对原汇总的净位移、路程、近停做一致性断言。两次JSON完全一致，SHA256 `6e547a7a75597cb222237e96955757d853cbf3f7fcc338df9003a6b9b3438c84`。时间线按status源时钟减事件接收elapsed的中位数对齐到query，偏移样本跨度0.156秒；以下秒数为近似，不冒充精确query裁剪。

- 搜索前30秒约30.65米净移动、近停9.73%；第90–120秒累计路程约6.26米、净4.18米、近停61.46%。流畅性在接近与失败恢复中恶化，不是整轮从启动起无法驱动车辆。
- 约110.4秒起的10.556秒长停：visible-target换向段结束，后续段`footprint_collision`拒绝；约110.7–120.1秒串行规划候选0–6，最后改点后才恢复following。不是车到目标2米内却终态未放行。
- 约90.5秒的6.238秒长停：观察目标`no_vehicle_path`→释放到GraphNav→多个候选失败→short_route_probe→following。约130.6秒的5.989秒长停也含3个长候选失败后才试短前缀。
- 四个最长停段全部telemetry_ok/actuator_ok，无source拒绝、无Native watchdog trip，最大遥测龄均<0.09秒，大部分采样在明确下发刹车。此证据排除了这些停段由已观测到的BeamNG遥测断连/执行RPC失败造成；`stale_command`是上游无新鲜运动命令时的控制归属，不等于网络掉线。

### 观察点与车辆可执行性，两次实际Smac对照

抽取本轮4组实际请求起姿、目标姿态和请求前最近公开`costmap_raw`字节，用实际已部署Smac源码/库、12米半径分别运行两遍。只在隔离诊断域创建规划组件，没有车辆动作、没有修改运行地图或控制配置；公开快照不等于现场搜索期间私有锁定快照。每组两遍路径结果一致：

前两组目标离车约3.86/8.00米，基于当前车姿经同点单圆弧的半径仅2.05/7.18米，均不足当前物理8米/规划12米；这不是所有可能路线均不可达的证明，但与实际规划多次换向一致。后两组同点兼容弧终点yaw已经等于原请求yaw，仍失败；因此不能把问题简化成“只改终点yaw就修好”。对照点是改位置的受控规划反例，并非已证明保留目标可见性、减少目标距离或可直接替代现场任务的最终方案。

源码交叉核对：`official_adapter/beamng_wildos_adapter/visible_approach.py::observation_step`按视觉方位±0.26弧度与测得自由直线选2–8米点，GoalStandoff加入地图连通/车身占位过滤，但没有证明从实际车辆当前起姿到该点的转弯/整段可执行性。bridge虽已尝试兼容弧航向，也不能修复点本身不适合当前车姿或地图的问题；随后串行候选及失败交接扩大停驶成本。

当前可闭合的主链为：短观察点仅获地图层面准入→车辆规划多次换向或失败→已接纳动作到头/下一段被最新图拒绝→停车串行候选→释放观察任务与探索重选。它解释本轮实测停段与折返，不证明全部历史失败均同因。83个掩码只有2条可靠深度、0确认，本轮尚未进入最终视觉到达门；视觉证据稀疏是独立未解决项。
