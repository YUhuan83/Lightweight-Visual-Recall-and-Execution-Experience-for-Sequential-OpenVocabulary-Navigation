# 普通 frontier 退役与运动交接修复（2026-10-16）

## 原因与范围

承接 `CANCELLATION_CHAIN_AUDIT_20261016.md` 的封闭现场反例：21 次取消全部来自 `frontier_resolved`，其中 19 次剩余段通过已记录公共全局图检查。意图失效被统一当作运动失效处理，触发取消、隔离、停稳、比较和重新规划。该原因还遗漏在同 frame 分类之外，错误清除行驶历史及独立恢复。

本次只改三份 Python 实现和一份测试，不改变模型、车速、车体、碰撞、转弯半径、原生规划器、目标到达阈值或记忆评分。

## 契约

- `frontier_resolved` 属于同地图意图退役：保留测得行驶轨迹、失败历史和有界恢复意图；独立恢复不因探索目标退役被取消。frame/query 等上下文变化仍完整清理。
- 仅已接受且归属明确的 FollowPath 可以完成当前段。要求没有规划/替换/待定 ACK/隔离/hold，odom、双地图、Native 控制新鲜且有效，裁剪后剩余段通过全局车辆约束及局部前缀检查。
- 剩余长度使用现有连续续接的 8m 范围；不修改已接受路径。过长、不安全、不能裁剪或归属不清时仍取消隔离。运行期间 RPP 碰撞检查、偏离/停滞/过期/执行器保护保持。
- 记录退役段的 epoch/serial/identity；单独失效已结束的 planner serial，不失效仍活跃的动作回调。旧意图仍在最多 64 项拒收缓存内。停止旧意图扩展，旧队列尾部不执行。
- 当前段终态仍必须经过原有实际 cusp/末点到达检查。完成后保留物理历史清理旧规划，将缓存的新路线重新送入 `on_route` 检查新鲜度、frame、query 与退役身份。没有新鲜路线则等待，不复活旧路线。不为已退役 frontier 发布观察到达 ACK 或障碍拒绝。
- query/frame/停车/执行模式变化、过期数据、Native 异常、动作失败仍使用原取消/隔离/恢复路径；晚到旧动作不能交接新目标。
