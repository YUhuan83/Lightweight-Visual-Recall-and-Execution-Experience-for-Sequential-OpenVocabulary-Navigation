# 2026-10-16 搜寻绕回加油站：完整决策链审计

## 结论与范围

审计冻结版本9bcaf8700786cbaf2ab40a22405121f20288fae5e8f51d6d777fbf5eb3d87997及session20261016_085025的642条GraphNav决策、45次Following、19份完整候选路径、316份评分快照；交叉核对前轮213429失败反馈。没有启动新仿真或修改生产代码。冻结435成员与当前本机源仍逐一一致；服务器无相关残留，版本相同。

主要问题在**探索选点、实际车辆代价、执行目标归属和搜索反馈**的交接。目前“路径合法并执行”没有形成“有效扩展搜索范围”的闭环。之前仅报告FollowPath失败0，不能作为整体规划正常的证据；这次明确补上上游决策与下游执行目标是否一致的检查。

本轮225.141米累计移动、最大离站40.634米、仍无目标视觉到达。没有目标mask/localization/confirmation、没有remembered_object_candidates/memory_selection，导航来源为graphnav探索。本轮没有证据表明把加油站确认为绿色房屋，或记忆召回将目标偷换为加油站。

相机没有检测到目标时，WildOS继续给几何frontier评分；这里的frontier_scores是探索/通行前景分数，**不是绿色房屋检测置信度**。所以0.8–0.9探索分数可以与目标mask=0同时存在。几何frontier由未知空间/碰撞距离等生成，相机曾看过某处也不自动等于几何边界消失。返回已知区域有时是去其它边界的正常通道，不能把整个加油站永久拉黑。

## 2. 确认的主要机制缺口

### P0：探索目标与执行目标没有共同的生命周期

- GraphNav发布642次决策，连续目标分组51次；Bridge的Following实际阶段目标只有5组。
- 640条首个动作之后的决策中，449条与最近Following记录的graph_goal相距>4米。该统计包含段完成/等待窗口，是不一致指标，不全等于“正在执行时又切目标”。原栈日志也确有route_deferred_while_planning_or_following。
- `planner_node.cpp:choose_exploration_goal`每份新评分图重新竞争目标；旧目标只有+.15保留加分，缺少“车辆已接受并执行此探索任务”的提交/释放约定。
- `GraphPathBridge.on_route`在following/pending时只更新latest_route，不立即改变已接受路线；这保护了动作/取消权限，但上游并不知道车辆仍执行哪个目标。
- 被上游当作当前目标的frontier，在642份决策采样时与车体最近距离约9.965米，没有一份<=6米。访问惩罚的完成条件是当前目标接近+朝向+低速停留；实际走完旧路径时，上游可能已经换了目标。这里没有保存每帧完整topology/current_node及私有visit计数，因此不能精确断言C++ visits始终为0，但不能假定其已经正确退役每个实际完成的探索任务。

**不能直接删除defer/取消保护。** 应建立有query generation/目标身份/route身份的提交、执行、观察、完成、阻塞和释放；旧回调只能结束其自己的任务。探索候选排名更新与已提交动作的归属要有明确边界。

### P0：短图段不等于短车辆轨迹，真实执行代价没有反馈到选点

- Bridge `max_segment_length`默认24米，限制的是图路线采样距离；没有把它作为实际车辆路径长度预算。17米端点也能产生74米/12段机动队列。
- GraphNav选点公式是heading utility乘物理置信权重、减.004×距离、减.08×visits、加.15当前目标奖励。没有输入实际车辆规划长度、换挡次数或执行时间。
- Bridge已有maneuver_cost=路径长+每次换向3米等价代价，但仅在同一端点的少量候选之间比较；观测heading候选会跳过普通候选比较，一旦可行就执行。它没有承担全局frontier之间的车辆代价比较。
- 真实车体必须按曲率与换挡执行；因此原图看起来近的目标，能持续占用车辆一分钟以上。新frontier排名在这段时间反复更新，叠加上面的目标生命周期缺口。

已用原on_plan_result方法、记录的70米/7段路径复现“观测heading候选直接执行，替代候选请求0”的策略行为。地图/跟踪验证器在该反例中是mock，不能由此证明同地图一定存在更短安全替代路径。地图私有快照、真实搜索代价和候选比较仍须单独重放。

**修复边界：** 必须把车辆路径长度/换向/时间预算接回探索选点；观测heading作为视野收益与执行代价比较，不能默认为必须完成的高代价泊车姿态。显式物体/记忆视点仍须保留严格视觉重观察与到达条件，不能靠放宽到达或转弯半径制造成功。

### P1：搜索覆盖的方向证据存储不完整

`GraphObservationStore.record_search_coverage`将heading_mask做OR，但所有方向共用一个negative_evidence=max。

原代码反例：方向0记录1.0，方向8记录.1，读取时方向8也被施加1.0。不同方向的证据强度串扰。查询仅按map/query/node UUID，节点替换后同区域的新UUID没有这条覆盖记录。

这是已复现的表示/接口缺陷；没有把内存数据库逐行封存，不能声称这两种情况已经在本轮特定frontier上发生。当前146条覆盖数量和最大效用差.191248只说明有数据和数值参与，不能证明已观察区域被正确处理。

**修复边界：** 按query/节点或可追踪区域/heading分别存储证据、来源与时间；重复同帧不能重复增强；新节点继承必须有可验证空间/方向关联，不能按场景名字封禁。

### P1：没有目标的证据与原始相似度混成一个数

`_record_negative_search`只在最终mask为空时触发，却用1-max(raw text similarity)作为absence strength。最终mask还经历了竞争类别、最小支持和连通域筛选；原始cosine不是校准的目标概率。没有mask既不能直接宣布目标不存在，也不能把一处高原始相似度当作整幅视野仍值得重复搜索。

原方法反例：raw max=.99、mask已被上游拒绝时，negative=.01，默认覆盖罚分仅.002；GraphNav保留当前目标奖励为.15。这是尺度不一致示例，不是本轮真实相似度分布或应调大权重的依据。

**修复边界：** 分别记录“有效观察过”“没有通过目标证据”“视野/距离/遮挡未知”，以有效观察和新信息收益管理重复探索；不能把无mask硬编码为整个区域空，也不能直接把1-cosine当概率。

### P1：执行失败没有进入经验学习的生产链

- `finish_execution_feedback`的eligible以succeeded为必要条件，并只发布OUTCOME_SUCCEEDED；失败只发diagnostic事件，learning_eligible=false。
- 消费端支持BLOCKED_GEOMETRY/COLLISION等负标签，但这条Bridge生产链不发送它们。
- 实际反序列化：前轮213429有执行受困、FollowPath中止两次失败诊断，但20条学习反馈全部SUCCEEDED；本轮28条也全部SUCCEEDED。
- 本轮628检索命中、28次写入、memory_modified_scores=0，与中性的成功先验相符。**写入了成功经验不能解释为已学会避免执行失败或重复搜索。**

需要更正此前过宽的功能描述：当前ExecutionExperienceStore消费端具备负反馈处理，但Bridge闭环尚未提供经过分类验证的负经验。

**修复边界：** 把可信的几何阻塞/碰撞、控制/跟踪失败、临时动态障碍、用户停止、旧消息和状态缺席分开。搜索无目标属于搜索覆盖，不能训练成地形不可通行；控制中断也不能标成静态障碍。应保留失败和执行代价记录，但只有满足来源/新鲜度/实际动作证据的对应类别才更新相应先验。

## 4. 按依赖顺序修复及验收

1. **先统一探索任务身份和归属。** 当前目标提交→Bridge接受→执行/观察→完成或可信失败→退役/重新选择。对旧/重复/延迟/乱序route、query切换、取消间隙、地图frontier消失测试；持续更新候选不能静默改已提交任务。
2. **接入实际车辆执行代价。** 同样的候选比较长度、换向、观察收益和可执行时间；闭环反馈昂贵/不可行候选，避免“短图段”悄悄变成74米动作。用封闭地图重放证明候选可达与恢复，不简单提高预算或强行截断造成未知停驶。
3. **修覆盖与经验数据约定。** 每方向的观察证据独立存储、按身份/空间严格关联，正负/未知与执行/搜索类别分开；可信失败才更新对应模型。覆盖多query/多实例/节点变化/重复帧，未观察方向保持可探索。
4. **再修统一时钟，并固定审计字段。** 当前时间戳偏移与真实延迟分开处理；至少记录提交/候选/拒绝原因、实际路径代价、完成观察、覆盖前后值和经验更新类别。高频日志需有界，避免为诊断阻塞传感器。
5. **组件与封闭重放通过后再现场。** 真实车体下同时验证新frontier覆盖增长、目标生命周期闭合、合理路线、目标视觉确认与到达；失败保留本轮RViz。先绿色房屋20轮≥16成功，再正式多目标。不得用目标mask或FollowPath成功单独计成功。
