## 主要判断

故障并不集中在一个规划算法。当前多层对“可通行”“目标失效”“动作成功”“消息新鲜”和“有效经验”的含义没有完全一致：上层的几何 frontier 消失会影响底盘动作；公开栅格允许的路线不必经过语义上可通行区域；局部动作成功不保证整体搜索进展；记忆有记录不代表产生了非中性决策反馈。

真实车体增加了不可原地转向、换挡、端点制动和大范围绕行要求，暴露了这些交接缺口。最后一轮三个新增记忆先验关闭仍失败，说明公共执行链有独立问题；这不能证明记忆实现正确，也不能把全部失败归为 BeamNG 物理属性。现有证据不能证明 WildOS 原论文原理失败；当前系统包含多层自定义适配，不能称为未经修改的原文基线。

## 问题与风险清单

证据等级：**现场**=冻结实测有对应事实；**反例**=实际方法离线复现；**源码**=明确实现/配置契约缺口；**待证**=需额外观测才能归因。各行不等于相互独立的 bug 数量。

## 已复核的正确边界

- 当前双costmap接LiDAR，RPP碰撞检查开启，真实车身与轮胎碰撞恢复；不能继续用历史“关闭碰撞/未接障碍”解释当前版本。
- base/后轴、平面nav_base_link与3D传感器坐标已分开；未发现本轮yaw/原点符号再次错误的反例。规划12m、控制8m和真实最小半径留有跟踪余量，并非单因数字不同就是错误。
- 上轮8468个applied回执匹配有效源，错误/无有效回执正油门为0。约195s静止中180.67s实际下发制动；这不支持“主要一直给油但物理困住”。ACK不证明真实轮胎力学正确。
- 到达判定仍要求新鲜语义/空间证据、实际位置及观察身份匹配；没有mask/3D时不宣布到达是必要保护。F03/F04应解决取得证据的能力，不能靠放松完成判定伪造成功。
- PassiveLandmarkIndex并非自动物体命名器：存特征/空间位置后按query检索。Graph中显示确定名称依赖语义确认。当前未证明同地图多目标记忆增益；关闭新增先验的搜索测试不是该实验。

## 为什么会相互放大

语义/地形约束未覆盖整条车辆绕行路(F05/F06) → 路径在后续地图上失效(F07) → 取消/重新比较/重规划(F08/F13) → 多短段和换挡停车(F14/F15) → 视觉覆盖和新视角不足(F03/F04) → 目标仍未确认。局部成功又缺整体进展退出(F11/F12)，负覆盖和执行经验反馈不能可靠纠正选择(F17–F20)。只改变任意一处门槛，可能把阻塞推给下一层，甚至产生F09/F10这样的新交接错误。

## 修复前必须共同固定的约定

1. 每个活动动作拥有不可变的query/frame/探索身份；后台新意图不能提前继承旧动作的失败、成功或取消权限。
2. 地图/路径/传感器都标明来源时刻与有效空间；“没有障碍数据”不能自动作为“已观察可通行”的证据。
3. 规划按真实运动约束、观察目标和执行成本生成；控制按实际位置裁剪及检查前方路径，停车/换挡的动态边界单独验证。
4. 对整体搜索进展和所有等待状态定义可解释出口，动作所有权不确定时必须保持安全停驶并报告可恢复故障。
5. 记忆中区分执行监督、语义历史、观察覆盖和候选代价。成功记录不能冒充有学习增益，未知失败不能强行标成不可通行。
6. 修改前反例、正常/失败/恢复/交接场景一起验证，再做受控实车体片段，最后完整搜索；必要验收未过不commit，不计稳定性成功。

尚不能静态证明全部运行时缺陷已穷尽。私有地图碰撞来源、调度锁耗时、实际刹车捕获包络和模型误识别真值仍需要专门证据。用户此后已授权修复，本报告是修复依据，不是修复完成声明。
