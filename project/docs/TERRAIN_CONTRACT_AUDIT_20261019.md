真实车体已发生车身接触和有驱动无进展，Nav2公开图允许。继续追查：WildOS输入是否保留了能够阻止同一路线的地形信息，还是在进入不同规划层之前就已丢失？

本轮区分两级证据：

- **实际记录重放**：22份占据图及22份地形GridMap全部从同一原始LiDAR/state/时钟映射重放，逐格完全相同，未匹配输入0。这里能证明真实消息含义。

## 2. 22份实际地图的结果

接触位置使用上一轮独立核验的引擎world节点坐标，分别变换到body后轴帧与gravity-level terrain帧，不能混用两种Z。

| 阶段 | 占据图 | 地形traversability | unknown | elevation_valid | 可证明范围 |
|---|---:|---:|---:|---:|---|
| 前6份，有可测低表面 | 0 | 0 | 0 | 1 | XY自由、存在测得的低表面高度 |
| 后16份，靠近/车体遮挡后 | 0 | 0 | 0 | 0 | XY仍自由，高度未测，填入的平面不能当作实测高度 |

本接口0表示自由/低障碍代价，1表示terrain障碍；不是将数值方向看反。

早期受阻位置附近3×3实测地形格，冻结C++指标给出：

- slope约0.146～0.157（rise/run，非弧度）。
- step约0.0747～0.0815米。
- roughness约0.0254～0.0296米。

这些值通过源码默认的slope<=0.35、step<=0.10、roughness<=0.08。**这只是同位置局部指标与源码默认限值的比较，不表示现场随机采样的某个GraphNav节点必然用同一3×3邻域，也未包含水平SDF净空或完整边检查。**

后16份elevation_valid=0时，诊断明确输出observed=false、限值判定null；没有把指标的默认0写成“地形安全”。生产源码确实另有未观测高度下的净空回退及physical_confidence=0，具体消费者如何使用这些元数据还需实际图回放核验，不能从XY自由直接推出所有物理观测完备。

## 3. 信息为什么在上游就弱化

### 3.1 占据图与Nav2共享同一过滤

`official_adapter/beamng_wildos_adapter/mapping.py::occupancy_from_points`调用Nav2共用的split_costmap_points，固定min_height=0.1、再按拟合地面ground_clearance=0.25去地面。此前独立接触邻域的低表面点因高度门槛未进入marking，但可保留clearing。

所以换一个下游规划器，并不能恢复已经未进入障碍图的几何证据。需要先统一车辆通过能力与障碍/地面判定。

### 3.2 terrain层不是原始障碍高度包络

`terrain.py::terrain_layers`先从occupancy得到traversability/unknown，再在0.5米格内取最低点附近0.15米以内的回波平均作为elevation。

这得到的是较低表面估计，而不是格内最大障碍高度或车体净空。格内高低突变可能被舍弃或平均；后续拟合地形指标面对的已经是压缩后的低表面。源地图重放逐格一致，排除了本诊断误用了另一份生成代码的解释。

Nav2路径及控制器仍主要依赖二维障碍costmap。先前审计确认完整车辆绕行没有统一沿路使用WildOS同一语义/坡度约束；这里进一步表明，地形指标本身也必须维护物理含义，不能只把当前terrain值机械叠到costmap。

## 4. 新确证源码反例：17厘米台阶被算成8.5厘米

当前 `graphnav_mapper/include/graphnav_mapper/terrain_metrics.hpp`：

1. 对高度样本拟合一个平面。
2. 从原高度减去这个平面。
3. 将残差最大值减最小值命名为step。

用0.5米间距3×3样本，x<0高度0，x>=0高度0.17，输入中真实阶跃明确是17厘米。实际编译的冻结C++输出：

| 项目 | 数值 |
|---|---:|
| 已知输入阶跃 | 0.17m |
| slope | 0.1700 |
| step | **0.0850m** |
| roughness | 0.04007m |
| 按源码默认三项上限 | **通过** |

对照：同总体高差的平滑17%坡面step约0；孤立30厘米突起step=0.30且被拒；不足5点observed=false。不是所有输入一律漏检。

这是**去趋势残差指标与物理最大可跨越台阶高度之间的契约缺口**。`RobotMotionConstraints.max_step_height`表示米制地形上限，但残差范围不能直接当真实阶跃。它属于当前适配版本的新增地形指标链；不据此归咎WildOS论文、RADIO识别或视觉记忆原理。

这个合成阶跃不是现场碰撞实体的精确断面。它独立证明算法约定有缺口；现场对应的实际邻域指标也偏小，是另一项真实记录证据，不能把两者合并成已测得现场恰好17厘米的垂直台阶。

不能只将step改成相邻格高度差：正常坡面也会产生高度差，稀疏和噪声可能放大。必须保留地面斜率、突变位置、观测尺度与高度包络，按同一车辆约束区分坡道、台阶、悬挑、粗糙面和未知高度，再一起验证规划及执行。
