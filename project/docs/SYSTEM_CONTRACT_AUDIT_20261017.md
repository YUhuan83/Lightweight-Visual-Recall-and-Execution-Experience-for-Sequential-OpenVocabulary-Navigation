# 冻结版本的系统审计与统一故障清单

2026-10-17。基于最后一次整车失败 `session_20261017_172053`，以冻结版本 `932ac9bf8cbe6444076f2ad702c560e0ab2eed781fdc749d7687998e75b38e44` 为准。本轮不修改生产实现、不新增整车测试，先统一归因和修复依赖，避免继续局部叠加补丁。

## 主要结论

现有系统的主要问题是**探索意图、车辆运动段与执行控制之间没有形成效率和连续性都经过验证的完整契约**。当前车辆物理约束是真实存在的，但上一轮大量静止是系统下发制动造成的，不能归结为车辆一直陷入地形。新记忆先验全部关闭仍失败，不能把当前主要执行故障归给记忆检索。

之前“规划基本没有问题”的判断不成立。GraphNav 完整图路、Smac 返回路径、局部动作成功、组件测试通过分别只覆盖一段链路。此前增加 frontier 退役后直接 reset/cancel 导致停车副作用，已有 10 月 16 日取消链证据；本轮仍保留 10 条跟随取消日志。这是改动的实际副作用，不应归为不可预见的模拟器随机错误。

本审计不能形式化证明不存在其它 bug，也未把未知项伪装成已定位原因。以下统一列出实证故障、源码缺口、风险和验收盲区，并说明哪些结论需要新的证据。

## 审计基线与覆盖

- 当前 400 个冻结载荷逐 SHA 与本机源一致；上次进程实际库和安装 Python 来源已核验。证据包整体 SHA、127 载荷 SHA、录像 SHA 沿用已验证封闭记录。
- 审查入口覆盖传感器时钟与坐标变换、点云与双代价地图、WildOS 评分/记忆、GraphNav frontier 生命周期、Smac 连续起点与候选搜索、Bridge 的规划/动作/恢复交接、RPP、速度环与 Native。
- 深入追踪的主文件见 `test_artifacts/system_contract_audit_20261017/version_check.json`，源快照保留。400 文件身份复核不等于每个依赖完成逐行正确性证明。
- 只读已关闭的上轮日志和数据库；没有读活动 SQLite，没有新仿真或新录像。服务器只执行已封闭地图的时间统计。

## 完整数据链应当满足的契约

| 接口 | 必须同时成立的条件 | 当前证据与边界 |
|---|---|---|
| BeamNG → State/相机/LiDAR → TF/odom | 源时钟映射一致；测量使用采集时位姿；base、后轴和 optical frame 有明确含义；m/rad/s 一致 | 原坐标、yaw、原点补偿与同范围过滤修复仍在冻结版本；本轮未找到坐标符号再次错误的反例。不由此保证每次传感器标注正确 |
| 点云 → GraphNav/两张 Nav2 costmap | 障碍来源、可观测范围、未知区域和碰撞体积含义一致 | 三套空间表示用途不同；当前无逐私有地图/原始点归因闭环，公开图路径安全不等于控制器最新指令弧安全 |
| 图 → 视觉评分/记忆 → frontier 目标 | 新鲜评分属于同 query/节点/heading；检索先验不能当到达证据；几何已知与语义已看过区分 | 670 次评分确实执行；新增存储先验实际为 None。几何退役并非视觉到达，整轮观察 ACK 为 0 |
| GraphNav → Bridge | 稳定探索 ID；末端是否完整；目标/观察 heading；退役与动作权限分开 | 生命周期已有所有权与相关拒绝协议，但普通退役仍频繁触发动作取消；持续缺失和无整体进展的退出缺口仍存在 |
| Bridge → Smac → Bridge | 同实际后轴起点、当前足迹、同目标、有限预算；成本和失败原因可追踪 | 完整路线选择已实施，但有界搜索失败不等于不存在路线；本轮 44 次底层空结果未显现在顶层唯一 no_vehicle_path 计数中 |
| 完整路径 → 单向运动段 → RPP | 路径可执行、换向成本合理、实际刹停可捕获端点；替换前复核、旧动作终态隔离 | 曲率/方向保护在，但几何 preview 没有动态制动模型；短段换挡与交接构成大量主动制动 |
| RPP → Twist → 速度环 → Native | 源身份/时戳/截止贯通；停车优先；回执对应当前需求 | 速度环之后已有源协议；RPP→速度环仍是无源 stamp 的 Twist，此处端到端源龄不完整 |
| 物体检测 → 3D/方位候选 → 靠近 → 重新确认 | 实例/时间一致；不足 3D 时有安全方位接近；到达不能仅靠 mask/action success | 本轮 mask 2、方位提示/3D/确认 0，未形成目标接近；此前 32 mask 的稀疏深度问题仍有独立历史证据 |

## 上轮约 195 秒静止的实际组成

`analyze_closed.py` 使用目标时间窗内 8474 个旁路 Native 样本，左样本保持到下一样本，间隔上限 .2s。控制原因以 **applied 回执 sender/generation/sequence 精确对应速度环源记录**；3900 个静止样本中 3848 个有此对应，其余单列，不用最近消息冒充匹配。总量与原独立积分一致。

| 源控制原因 | 静止时间 | 含义 |
|---|---:|---|
| stale_command | 96.541s | 速度指令超时后制动；结合状态多在规划/比较/地图等待和退役之后，不自动等同网络丢包 |
| gear_change | 62.106s | 前后换向期间主动制动；当前每次换向确认 2s |
| tracking | 14.327s | 源分类为跟踪；不意味着正油门、物理受困或持续有效位移 |
| execution_hold | 10.922s | 动作隔离/交接的执行保持 |
| ackermann_stop | 5.027s | 零速度/端点停车等控制停车 |
| disabled | 3.450s | 初始启用或关闭过渡 |
| 未匹配或未 applied | 2.624s | 不强行归因 |
| **合计** | **194.997s** | 与独立原积分一致 |

按实际下发量再独立分区：180.670s 为 brake >.1，13.831s 为滑行/低扭矩，正油门 >.1 且 brake≤.01 仅 .495s。SDK 输入/回执不是物理制动力测量，但足以反驳“这 195 秒主要一直给油却走不动”的归因。

`following` 状态中的静止约 79.17s，其中约 62.11s 精确对应换挡。对应旁路最新 Twist 接收龄最大约 .100s，未发现这部分存在 >.5s 的旁路收流缺口。因此不能把这 79 秒全部称为 RPP 没发指令。

## 统一故障与风险清单

| ID / 优先级 | 模块与问题 | 证据等级 | 修复依赖与验收要求 |

A01/A02 是本轮主动停车的主要处理方向；A03 是实际车辆执行成本；A04/A05 是已复现源码缺口；A06/A07 有明确契约风险和历史/本轮失败证据，但具体占比未全部确认；A08/A09 是目标与记忆验收链的独立缺口；A10 解释了为何过去总能在下一轮再发现之前没测到的问题。它们不能压成一个“换规划器”或“关物理”的单一补丁。

### 关于地图时间戳的进一步限制

map_timing.py 只读关闭录包，统计目标前 5 秒至目标结束的公开消息，以便匹配最早等待。全局图 receipt gap P95 1.741s；生成时戳到录包接收龄 P95 约 .0027s，不支持单纯“大量网络传输延迟”的判断。34 次 waiting 状态发布中仅 16 次在旁路也表现为最新递增源图接收龄 >.75s，剩余差异须对齐 Bridge 真实回调入口/拒绝路径和公开状态保持，不得把所有 43 秒都解释成地图没有发布。私有地图锁占用、调度、序列化和更新耗时占比仍未知。

## 已复核而不应重复推翻的部分

- 原点/理想载体 yaw 补偿、当前真实后轴坐标、LiDAR terrain 同范围过滤、query ready+ACK、清 costmap 后 current、异步旧回调隔离仍在冻结版本。没有新反例前不重做这些修复。
- 当前 planner 半径 12m、controller 8m、物理能力约 7.45m 是留跟踪修正余量的设置，不是仅因数字不同就认定接口错位。
- 双 costmap 均已接障碍观测，RPP 碰撞检测开启；过去“没接 LiDAR/关闭碰撞检查”的旧故障不能再当作当前配置事实。
- 源控制 8468 回执匹配、错误/无有效回执确认正油门为 0；执行器故障/遥测不健康为 0。它们不证明端到端动态执行正确，但也不支持“BeamNG 总没执行指令”的泛化。
- 记忆组件更名没有产生额外第五份存储；`:memory:` 与有界轻量索引仍在。同进程记忆目标不改为跨进程持久化。

## 修复顺序与停止叠加补丁的门禁

1. **先处理 A01/A02 的事务与连续性。** 列出意图、动作、替换、取消、停止、恢复的单一归属和权限；保留现有安全条件。用本轮真实取消/等待/规划失败序列作为跨模块反例，检验没有新动作死锁、旧目标复活、旧回调越权或无限空等。
2. **一起处理 A03/A05/A06 的车辆执行契约。** 先贯通控制器源龄和动作身份，再用实测延迟/减速验证实际可捕获的段和换向；按预计执行耗时评估路径与目标位姿。几何反例、正常前进/倒车、停稳换向均通过才做长路线。
3. **处理 A04 的整体进展与目标有效性。** 明确暂时缺失、持续缺失、有效绕行、原地往返与新 query，避免“加一个时间阈值”制造新的错误退役。
4. **闭环 A07 地图来源，再验 A08 目标接近。** 在相同封闭数据上回放障碍与实际弧，记录拒绝的最早接口；目标链按单项证据逐级验收。模型短缺保持单独问题，不用场景关键词适配补几何问题。
5. **最后验 A09。** 共同行驶链通过后，同一次加载依次换目标测试真实记忆增益；20 轮至少 16 成功的用户验收条件保持。A10 的因果诊断与跨模块回归贯穿前面各项。

组件、录包反例、现场受控车辆行为和完整目标成功分别报告。没有必要组件门禁通过前，不再以反复运行整轮 420 秒代替根因验证。完整验收未过不 commit；修复前后范围和证据继续更新到项目记忆。
