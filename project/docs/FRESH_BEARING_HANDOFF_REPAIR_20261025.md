# v27 / v28 定位新观测与错误回看修复

2026-10-25。用户要求修改走停和目标确认问题。当前使用独立候选，保留 v26、v27 和主工作区的用户改动，不以组件通过代替完整验收，不提交 Git commit。

## 已证实的问题及最小修改

1. `ObjectMaskTriangulator.process_observation` 原先在机器人位移不足1米时直接返回。这个门本应控制独立视点存储，却连带丢弃当前新掩码，即使已有有效基线也不重新定位。v27 将独立关键帧存储与当前观测求解分开：近距离新帧与相距至少1米、未过期的历史相机射线重新求交；临近历史射线不重复加权，不增加关键帧，不刷新旧锚点寿命。当前射线必须参与，仍经过原基线、视差、重投影、条件数和不确定度门。没有复发旧解，没有修改 LiDAR 点数、四帧共识或2米到达阈值。
2. 原连续补路对所有候选一律要求距旧动作端点至少4米，错误地把“同一目标避免重复规划”的规则用于新目标。真实桥接回调反例：正在执行0→12米，收到新 frontier 的14米目标，实际请求变成8米；新10米目标同样变成8米。v28 将过滤提为共享策略方法，只有已确认的当前动作 epoch/serial、相同 query generation 下目标身份改变时保留新候选；同目标、旧 epoch、未确认动作仍维持原4米过滤。此处只允许规划，路径替换仍走原实际位姿、车身/地图、方向、动作接纳和停车屏障。
3. v27 现场131.47秒出现 `side_lookback_preempt`，将实际目标接近取消，随后出现车后6米点 `(720.4143,-64.6177)`、朝向约-1.486rad。131.75–151.21秒串行请求14个位置/朝向候选，151.65秒才跟随，形成最长20.72秒近停。源码 `maybe_side_lookback` 仅凭附近25个以上障碍格推测“目标建筑”，将当前系统时刻填写为新视觉观测时间，并可抢占真实目标。这违反障碍几何与语义观测的身份/时间契约。两个回调反例均失败：无视觉观测仍产生后方目标、前方实际10米目标被改成后方6米。v28 删除这个自动回看生成函数及 `start_segment` 中调用；保留障碍碰撞检查、真实视觉提示和 GraphNav 探索/观察流程。历史 lookback 消费/清理状态暂保留兼容，生产不再由匿名障碍格置入该模式。

## 保留的上下游约定

- 目标/实例、query、掩码采集戳、相机采集姿态与 LiDAR 采集姿态契约不变；不修改坐标符号、SBR参考点、单位、车体/轮胎碰撞或转弯半径。
- 多视图历史仍受原5秒寿命约束。连续重复、乱序、过期、旧 query、歧义深度都不能进入新确认。固定点的四张新掩码可各自重新求解，不等于新增四个独立基线。
- 不通过放宽最终到达/记忆可信度解决定位稀少。定位语义正确性仍须现场图像核实；一条掩码或求交成功不是完整成功。
- 新目标补路规则不会撤销旧动作、跳过车体检查或复用旧未执行倒车尾段。已有取消、租约、ACK与迟到 Future 隔离回归保留。
- 删除回看意味着不再因任意近邻障碍额外倒退观察；实际目标的新鲜视觉提示、frontier观察和正常恢复继续工作。
