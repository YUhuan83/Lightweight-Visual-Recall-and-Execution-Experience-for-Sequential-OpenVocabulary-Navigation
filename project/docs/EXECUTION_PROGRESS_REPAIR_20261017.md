## 原代码反例

`reproduce_progress_budget.py/.json` 保存了原始方法反例。新增 9 项初始回归中 6 项在原代码失败：

1. 同一目标沿相同短段往返，每次局部前进又清零次数。
2. 完成局部 prefix 无条件清零，距离整体目标仍远。
3. 同一交易的图路线形状或 prefix 末点变化可清零次数。
4. 换了探索交易但坐标相同，反而继承旧交易的耗尽次数。
5. 连续小段取得累计一米新进展，原局部逐段判断不能识别。

初次测试夹具错误使用真实 Clock 给合成路径打戳，使 on_route 场景未实际进入；修正为与合成 odom 同一时钟后保留 `before_tests_corrected.log`。初稿直接导入 TestCase 导致 unittest 重复收集，已改模块别名，按新类明确计数。没有为通过测试放宽生产保护。

## 修改及上下游契约

本次只改生产实现 `nav2_adapter/wildos_nav2_adapter/graph_path_bridge.py`：

- 恢复状态绑定 query generation、frame 和 exploration_id；探索目标使用元数据中的真实整体 goal，不能使用可变图 prefix 末点代表目标。没有交易元数据的旧目标保留原 4 米目的地变化分界。
- 在正常规划入口绑定基线。只有身份有效、到达条件独立核实、输入新鲜的动作完成回调，且比已记账的最近目标距离再前进至少 1 米，才恢复次数。累计短段可以记账，走回原处再走同一段不能重复记账。允许绕行暂时远离目标，但远离本身不恢复次数。
- 同一交易换图路、换 prefix 或地图变化不恢复次数；耗尽时精确拒绝当前探索路线，显式物体/记忆目标仍受原拒绝保护。新目标不会继承旧目标的 block 和重复规划抑制。
- 原有异步 epoch/serial、动作取消隔离、2 秒掩码、真实到达、车体碰撞、局部/全局地图、曲率、速度、转弯半径和源控制协议保持其原验证条件。
- `reset()` 清理新状态。实际测量走廊 escape 的独立成功恢复流程保持原行为；本轮没有该恢复动作，不能将其当上述短段清零反例。

新进展采用已确认位置到稳定目标的欧氏距离；它不能精确评估长障碍绕行的剩余行驶成本。该修正恢复原有三次重试边界，不能单凭它保证优质路线、足够探索或真实可达。
