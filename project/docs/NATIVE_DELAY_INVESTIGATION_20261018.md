## 测量链路

记录 issued_wall_ns → DDS source_timestamp → 内核 UDP 到达戳 → Native recv 返回 → DDS received_timestamp → 执行器创建订阅任务 → take_message 调用前/后 → on_control 前/后 → Native 控制遥测/源身份回执。

- 各 wall 时间保持 UNIX 时钟身份；内部耗时优先用同进程 monotonic 差值。
- Humble 的普通订阅回调不会接收到第二个 MessageInfo 参数。诊断执行器保留底层 take_message 返回的元信息；不修改系统 rclpy 文件。
- UDP 观测库只在 Native 进程生效，记录指令序号、原源戳、接收时间及 fd/tid，不保存网络载荷。它是运行诊断插桩，不属于生产修复；有观测开销，不能把本轮当作无插桩稳定性统计。
- ioctl SIOCGSTAMPNS 在未启用时间戳时可能延迟生成接收戳，初版回归发现此问题后弃用。当前通过 SO_TIMESTAMPNS 辅助数据获取真实内核戳；实际 UDP 载荷保持/时间顺序回归通过。

## 下一步判定要求

1. 延迟出现时，先用同身份指令的内核/recv/DDS/ready时间确定最早阻塞区间，不能将DDS received_timestamp直接等同于内核到达时间。
2. QoS或接收架构候选必须覆盖更新间隔和实际应用源龄；“每次拿到的消息新鲜”不能掩盖长时间没有新更新。
3. 验证丢失、重复、迟到、乱序、源重启/代际、制动屏障及停机：不能放松现有源身份、原截止或车辆本地租约。
4. Native候选验证通过后再与保留的Smac候选合并、冻结并验收。目前没有Native生产修复，也不宣称已查清到最终库内根因。
