## 数据流核对

正式物理入口为`physical_vehicle_control.launch.py`：原始SBR → StateSensor → 官方adapter后轴姿态/速度 → mapper/frontier与Nav2地图 → GraphPathBridge → Smac CarLike → 路径检查及换向分段 → Ackermann RPP → 速度/换挡环 → native控制。
目标记忆改变候选目标选择，随后走同一车辆路径与执行接口；这些共用接口的失败并不能单独证明记忆检索算法有错。

- 坐标：活动入口使用官方adapter，不是通用`state_odom.py`。后轴偏移(-2.172,0.330)、轴距2.501m、前3.4/后1.05/半宽1.05m仍在当前代码中。物理传感器3D frame与yaw-only/z=0的`nav_base_link`分离仍有效，避免52m海拔与pitch产生假横向误差。未发现这些旧修复被覆盖；本次未重做现场标定。
- 时间：当前代码保留源时钟→ROS锚点映射、重复/倒序拒绝、重启清历史和测量插值。pilot3方向振荡窗口的接收新鲜度支持执行逻辑问题；原始两时钟的约29853秒偏移不是通信延迟。接收新鲜不能证明所有传感器采集/推理始终无延迟。
- 状态：请求/result有epoch及candidate隔离；执行前重查地图；换向后检查真实车姿和两图接续。这些既有保护保留。本次发现的首次接入缺口不能通过删除碰撞保护、放宽到达容差或缩小车体解决。
- 车体：本机真实模式仍保持车身/四轮碰撞、8m曲率、禁原地旋转、障碍标记/清除及FollowPath碰撞预测。历史实际车辆结构/组件证据有效；本次离线不能确认服务器当前进程及加载参数。
