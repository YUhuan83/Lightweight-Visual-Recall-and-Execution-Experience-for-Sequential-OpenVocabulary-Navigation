# 同目标重试准入修复（2026-10-17）

## 查明的问题

继续检查“同目标没有整体进展却反复重规划”，在现有执行进展归属修复基础上复现三条缺口：

1. `on_route` 对失败后形状改变的图路线允许再尝试，但只有地图改变的分支递增 `recovery_attempts`。同目标换路线可绕过重试计数。
2. 失败阻塞按路线末端 4m 范围匹配。即使探索 ID 和实际目标不变，部分路线末端移动较大仍会跳过这段重试准入。
3. `retry_when_planner_starts` 在次数耗尽时直接返回。没有新路线消息时，不触发既有探索拒绝接口，只留下旧目标。

这些是生产方法的可复现逻辑缺口，尚未将每条分支逐一映射到上轮现场的全部停驶时间。不能据此声称找到了所有停驶根因。

## 修复与影响

- 本轮只修改生产 `nav2_adapter/wildos_nav2_adapter/graph_path_bridge.py` 及其 `test_execution_progress_ros.py`。
- 新探索 ID 仍通过现有 `sync_recovery_progress` 清旧预算和阻塞。同一 ID 的换路线/部分末端变化不再获得不计数的尝试。
- 重试只在实际重新准入时计一次；相同受阻路线、活动中重复消息不计。`execution_unavailable` 与既有定时器一致，不把通信恢复当作执行失败计数。
- 定时器在退避期结束、没有活动/待接受动作或隔离中的旧动作、输入和执行器新鲜、服务就绪时，可以在预算耗尽后发出探索拒绝。成功发出后转入 `route_recovery_exhausted`，不在每个定时器 tick 重复发送。
- 继续使用原精确路径/目标拒绝协议；显式目标、记忆目标、query reset 不获得探索拒绝权限。没有新增区域障碍屏蔽、成功 ACK 或失败地形学习。
- 原实际到达核验后的真实整体进展记账、新 query/新 ID 重置、旧回调隔离和曲率/碰撞保护保持。未加“单纯计时即退出”的策略：有效绕行可能暂时远离目标。
