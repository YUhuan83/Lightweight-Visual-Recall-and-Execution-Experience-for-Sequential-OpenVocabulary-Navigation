# 2026-10-17 离线闭环审计

## 结论

当前至少有两条独立的闭环缺口，不能继续用“FollowPath 有路径 / 某轮没有 abort / 几百项回调通过”代表系统正常：

1. **执行闭环没有保证最新控制需求及时替换旧需求。** 速度环已经输出制动，Native 仍向车发旧油门；接收端又把晚到旧消息从接收时刻重新计龄。新鲜遥测、成功 RPC 和车辆租约心跳不能证明当前源指令已执行。
2. **探索目标保持没有持续有效性和整体进展出口。** 原节点消失后，可以持续沿旧坐标规划；局部动作有移动不等于接近或有效探索该目标。

此外，几何跟踪预检没有车辆速度、制动和指令延迟模型，不能证明真实车体能在严格 cusp 范围内停稳。三个新增记忆先验关闭时这些故障仍发生，故不能把这批执行故障归为视觉记忆理论失败。

本轮只进行本机源码核验、封闭数据分析和反例复现，没有连接服务器、运行新仿真或修改生产实现。保留此前修复，不新增场景阈值或放宽保护。

## 二、最明确的执行故障：制动在上游，旧油门在下游

在整段执行窗口，找到 **54 个采样点**：最近 0.1 秒内速度环已经输出 `throttle=0, brake>0.2`，但 Native 的 `sent` 仍为正油门、零刹车。这是采样点数，不是 54 次独立事故。

五次预瞄反向中止的制动链：

| 目标执行时间 | 几何预检 | 从速度环持续制动到 Native 首次下发非零制动 |
|---|---|---:|
| 187.004s | 通过 | 0.678s |
| 191.373s | 通过 | 0.628s |
| 197.793s | 通过 | 0.585s |
| 206.901s | 通过 | 0.382s |
| 211.128s | 通过 | 0.430s |

前三段还保留实际 `/wildos/native_control` 消息。按 throttle/brake/steering/gear 完整值精确匹配，12 个 Native 下发样本匹配到的源输出，**至少已旧 0.274–0.436 秒**；此时 Native 自报的接收后 `command_age` 却小于 0.05 秒。

具体例子：源控制消息在 `1792155513.504946709` 已被独立记录器收到，Native 在 `1792155513.9410675` 才下发同一组油门/刹车/转向/挡位，至少相差 0.436 秒；Native 自报 `command_age=0.023355s`。重复值取最晚匹配，给的是保守下界，不冒充精确 DDS 回调进入时刻。

因此最早可定位范围是：**控制源发布后 → Native 消费/下发前**。不能再把这五次主要解释成“全局没有路径”“速度环没有算刹车”或单纯轮胎受困。

Native 的统计也不支持将全部延迟解释为慢 SDK RPC：

| 项目 | 中位数 | P95 | 最大 |
|---|---:|---:|---:|
| 控制 RPC | 5.388ms | 16.792ms | 134.457ms |
| Native 控制定时周期 | 50.0ms | 51.5ms | 135.2ms |
| Native 遥测样本龄 | 55.5ms | 67.2ms | 185.1ms |
| 接收后命令龄 | 26.2ms | 171.1ms | 482.1ms |

这不排除调度/IO 的贡献。DDS 可靠传输重发、执行器回调调度、共享负载分别占多少，当前数据仍不能区分。此前准备的 QoS 对照没有运行结果；**不能宣称改 BEST_EFFORT 一定能修好，也没有据此改生产 QoS。**

## 三、源时间与回执约定确实缺失

源码位置：

- `nav2_adapter/wildos_nav2_adapter/native_vehicle_control.py:135`：`on_control` 只接没有 header/源时间/序号的 VehicleControl，随后以当前 `time.monotonic()` 写 `command_at`。它计的是收到消息后的时间，不含此前投递/排队时间。
- 同文件 `:40`、`:227`：允许将上次接收的指令保持到 0.8 秒；控制定时器可持续重发该旧需求并更新车辆租约。
- `nav2_adapter/wildos_nav2_adapter/execution_feedback.py:86`：`execution_transport_issue` 核对遥测、执行器状态和 RPC ACK，没有将 ACK 关联到某条源控制需求的 identity/sequence/deadline。
- 当前 Lua ACK 证明一次请求得到响应；租约证明同一执行者仍在喂心跳。两者都没有直接证明执行的是最新源控制需求。

已用当前生产方法离线复现：

1. 一条生成较早、但晚到回调的油门指令，被按收到时刻重新变年轻，仍可驱动。
2. 已缓存油门保持 0.7 秒时，只要遥测新鲜，现有 0.8 秒门限仍不触发 watchdog。
3. Native 遥测新鲜、RPC 成功，但需求已经保持 0.44 秒时，上层健康检查仍返回可执行。

这些是现有接口/状态约定的反例，不是已证明现场发生 DDS 消息乱序；ROS 单个发布者的顺序保证、进程重启及多发布者场景需分别处理。

## 四、几何预检与真实刹停之间有缺口

`tracking_preview.py:19` 的输入是 points、headings、pose、radius 和几何容差；`:82` 按固定空间步长积分，没有当前速度、控制延迟、制动能力或挡位传动模型。

本轮五条失败路径从记录的实际起点重跑，全部仍被当前预检判为可到达。4 条在采样中记录到了满足 0.2m / 0.35rad 的 odom 姿态，但同时邻近 Native 速度仍约 1.3–1.9m/s；另一条采样跨过范围，没有采到满足条件的点。**更正此前“5 次都记录到进入终点”的宽泛表述。** 这些 odom 是带延迟的记录姿态，也不能当作同一时刻真实车体已经停稳。

在 1.2m/s 下，仅保持旧需求 0.44 秒就对应约 0.528m 位移，尚未计入制动距离，已经超过 0.2m 捕获范围的直径。由此可见，几何可跟踪不等于存在可执行的速度/刹停过程。

`ackermann_rpp/src/controller.cpp` 已有进入严格终点后发零速度、单向路径反向保护及实际弧碰撞检查。这些保护揭露了上游/执行延迟与刹停不一致，不能通过删反向保护、放宽 cusp 阈值或关闭碰撞宣称解决。

## 五、上层探索还有独立缺口

复核已取回、逐成员校验的 `target_progress_review.json` 及源码：

- 目标 35 被持有 161.591 秒，车辆累计行驶 78.419m；最近 odom 距离仍 12.991m。
- 259 条图路线状态中，只有 24 条为完整路线。
- 首份匹配拓扑中目标 UUID 存在且为 frontier；中段、末段两份匹配拓扑中该 UUID 缺失。
- `planner_node.cpp:275–299` 的持有分支继续返回原目标坐标；`exploration_target.hpp:61–71` 对缺失节点返回“未 resolved”，没有持续缺失期限或整体路径进展预算。

所以局部动作持续有位移时，高层仍可能长时间追旧意图。这不是上一轮“同 UUID 明确变 non-frontier”的同一个反例：此前修复保留，当前缺的是**暂时丢失后的有界重关联/重新确认及无整体进展出口**。两份快照不能证明整个中间时段连续缺失，不用单帧缺失立即取消。

## 七、为什么之前测试通过却反复出问题

1. 回调测试大量使用立即执行、无排队的 mock；没有验证源指令生成到车辆下发的总年龄。
2. RPC ACK / 遥测 fresh 被过早当成控制闭环可靠，而缺少当前需求身份的对应关系。
3. 几何预检是空间积分；真实车体需要带速度与制动的时间过程。原有 bicycle replay 也不能替代真实传动和消息延迟。
4. 原“普通退役必须取消”的测试还固化过错误契约；观察到局部效果后继续整轮测试，没有先锁定控制链的端到端验收门。
5. 系统同时改变探索策略与物理执行，故不同轮次在不同轨迹上暴露不同问题。后续必须分别冻结并验收每一层，不能把通过数量当作稳定性。

这些是本项目此前排查和验收设计不充分的地方，不是用户应该再调整目标来配合代码。

## 八、修复顺序与具体验收

1. **先修控制需求的源身份/源龄/回执关联。** 设计带源时间域、序号、会话身份和截止期限的 Native 控制封装；接收方拒绝过期/旧会话/旧序号，不能因晚到或重复包续命。下发状态回报实际对应的源序号。保留单执行者租约、原生制动、取消隔离和状态新鲜度保护，默认 `/control` 兼容入口须单独评估。
2. **定位实际延迟来源。** 在每个边界留可关联的轻量时间与序号，对 DDS QoS、执行器回调调度分别受控比较；先做不移动车辆的组件实验。没有实验结果前不直接切协议或加并发线程掩盖问题。
3. **控制链合格后再验证真实刹停。** 以当前速度、位姿不确定度、指令延迟上界和测得制动能力形成可达/停止约束；几何预检保留为其中一项。覆盖前进、倒车、短 cusp、长段、减速、停稳及恢复；不靠全局降速或放宽到达阈值通过。
4. **再补探索目标有效性/整体进展。** 连续缺失需由新鲜独立图帧确认，做有界空间/方向重关联；以剩余可执行路径代价、图进展和新区域覆盖核验持续进展，允许必要绕行。失效意图通过已有安全短段交接；不立即取消所有动作，也不无限追旧坐标。
5. **最后恢复记忆增量与完整搜索验收。** 先建立共同适配正常的受控基线，再逐项启用记忆；当前没有达到 20 轮至少 16 成功的条件。
