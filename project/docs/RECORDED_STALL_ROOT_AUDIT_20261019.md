## 四、时间戳核验和限制

- 129份已录state映射记录均找到原state与同mapped stamp的odom；mapped-source等于记录offset，重启0。130份LiDAR published记录，六个过滤重放时刻state/LiDAR源戳差均0。
- BeamNG ROS bridge先把引擎秒数锚定到一个ROS epoch；adapter又映射到输出ROS时钟。StateSensor.header不是可直接与obj:getSimTime比较的秒数。安装vehicle.py的_compute_time_offset与publish调用已只读核对。
- 未找到移动中Native与StateSensor完全相同的SDK载荷配对，故没有声称得到精确的objSim→StateSensor锚点。接触到传感器时刻目前使用邻近Native sim/wall样本及随后选择的已录cloud，不是同一次采集的精确联接。
- 以上仍足以核验实际过滤输入输出；不足以宣称所有时钟重启/乱序问题已解决，也不解决历史Native间歇DDS迟滞。

## 五、从完整系统看，这次排除了什么、留下什么

1. **物理受困可独立发生**：本组件没有视觉交接，仍复现有驱动无进展和车身接触；不能只改视觉计时器期待车辆自动通过该区域。
2. **地图输入存在实际信息损失**：早期真实低表面回波在高度过滤丢失，地图继续允许。需要统一地面可信度、台阶/低矮实体、底盘净空、车体扫掠和clearing语义；不能只把Smac搜索预算或FollowPath阈值放宽。
3. **完整任务的恢复仍有两个独立确证缺口**：视觉超时清掉物理恢复记录/意图，成功clear累积耗尽预算后拒收新路。它们在本组件被隔离，没有实施生产修复。
4. **实际越障包络和动态接入仍缺标定**：二维footprint与转弯半径不能覆盖底部接触、坡折、换挡/制动时间。由原真实车体证据定义公共约束后，再联动规划、控制及任务恢复；保留原取消/停稳/旧响应隔离。
5. **精确碰撞对象和向量参考系仍待独立采集**：回调没有对象名称；不能据录像或material_id直接宣布撞到某棵树、路沿或长椅。下一次应同时读节点位置、车辆原点与引擎时刻来验证回调坐标，随后才做同物体空间归因。
