# 观察位姿选择与规划失败交接（2026-10-21，离线候选）

## 问题与范围

针对212436、210759等轮次的观察点规划失败后重复等待。本次使用当前未提交工作区，
不恢复旧版本，不修改Smac、反向惩罚、车体、速度、换挡、确认门槛或到达判据。
服务器不可用，未连接、部署或启动仿真。

原可见接近点和环形standoff只在 `/spot1/local_map` 上检查中心射线和余量，
无法证明非对称车身能够占据终点，也未剔除Nav2地图上不连通的中心区域。
已确认目标已有替代观察流程，但bearing-only目标耗尽规划候选后仍保留接近状态到超时。

## 修改

1. `nav2_adapter/.../observation_pose.py`：按Nav2栅格原点及旋转计算车辆所在的已观测自由
   连通分量，中心格须为0–98，再检查既有SBR footprint/padding。
   Nav2已有inscribed inflation，不再次膨胀地图。四邻域连通只作必要条件，
   不作为Ackermann转弯可达性的证明；Smac和执行侧扫掠检查保留。
2. `GoalStandoff`接收 `/global_costmap/costmap`；同一消息和车辆中心格缓存连通结果。
   既有五条方位射线逐格缩短到至少2m，并复用既有24角度standoff环形候选，
   跳过不满足车身/连通条件的点。最终射线回退也检查同一条件，不能绕过过滤。
   已接收到车辆图后，过期图不能生成新位姿；尚未收到车辆图或ideal_point沿用旧提案行为，
   下游规划准入仍然生效。因此不能将提案发布称作已经规划可达。
3. bridge对bearing-only目标的明确几何/空路径失败立即释放接近状态，发出
   `visible_target_no_vehicle_path`，复用原动作终态/停车/reset屏障；传输、协议、
   地图新鲜度失败不作为目标位姿不可达证据。
4. 选点端消费该状态及`confirmed_approach_failed/no_vehicle_path`，对匹配查询、
   新鲜来源戳及当前目标位置的失败做15s有界避让（visible半径2m，确认位姿1.2m，
   沿用原桥的相关尺度）。重复/旧/其他查询反馈无效；最多16项，切换查询清空。
   可见目标用原mask戳重新提出别的位置；确认目标复用`approach_refresh`，原观测戳、
   对象位置和instance_id不改。refresh仅为导航种子，不产生新的确认或到达证据。
5. 既有`start_live_observation`在试替代确认视点时也应用相同连通/车身必要条件，
   继续走已有GraphNav、Smac和失败后交接，未增加另一套动作所有者。

## 反例与验证

改前6项定向用例中5项失败、1项保护路径通过，零加载错误：自由中心但车身压障碍；
不连通的自由终点；环形点车身碰撞；射线回退绕过车辆条件；无路仍等待超时。
初稿修复后“不应发布”的夹具沿用detect返回值导致一次AttributeError，改为直接送mask，
未改变生产逻辑迎合测试，日志保留。

最终16项定向用例通过，含：上述反例、原戳/实例保留、失败位置切换、未知/过期/旋转地图、
重复与跨查询反馈、传输失败不误伤、确认失败进入既有同实例恢复，以及实际生产
on_plan_result回调失败→新提案→路线准入链。规划结果/服务/地图为合成输入，
无实际Smac、ROS序列化/DDS或车辆，不能称作现场验收。

完整接口替身回调678项，677通过、1失败、0错误。唯一失败
`test_side_lookback_turns_back_once_near_large_structure`在本次改前源重载后同样失败。
官方适配器纯函数32项通过。新测试加入`tools/offline_callback_check.py`。

320×320全自由地图单次连通计算本机约47.25ms（102400格）；同消息/中心格缓存命中
不重算。服务器运行负载、前后端消息时序和稀疏地图误筛仍待现场检验。
