# 理想点载体与真实 SBR 对照（2026-10-13，离线）

用户观察理想车体没有当前真实车体的接续/反复重规划问题，与当前源码差异一致。但两套模式切换了规划器、控制器、轮廓、分段和执行接口，不是只改变物理碰撞的控制变量实验。本轮核对本机当前源码，未重新核验历史每轮服务器部署。

## 先区分两种理想模型

项目 `ideal_point` 允许平移和 yaw 独立，包括 `v=0,w!=0`；Lua 直接积分并更新宿主位姿。上轮离线审计的零延迟自行车仍有 8 m 转弯半径，不能原地转向。上轮“零延迟模型也失败”指后者，没有重现用户理想点载体的完整搜寻失败。

## 当前实现对照

| 环节 | ideal_point | 真实 SBR / ackermann |
|---|---|---|
| 全局规划 | NavFn / GridBased，二维栅格 | 自定义 Smac 包装 / CarLike，REEDS_SHEPP，72 朝向，8 m 半径 |
| FollowPath | 原版 RPP，允许原地转向，不倒车 | 自定义 Ackermann RPP，禁止原地转向，允许倒车，曲率限制 1/8 |
| Twist 执行 | 独立 v/w 直接积分 XY/yaw | 转油门、制动、挡位、转向，随后由真实车体产生运动 |
| BeamNG 车体 | 所有节点 fixed，车身/轮胎碰撞关闭，理想模式隐藏车体网格；保留传感器 | 原始车身/四轮碰撞、转向机构、动力/制动/轮胎有效 |
| Nav2 轮廓 | 半径 0.15 m 代理，局部膨胀 0.3 m | 后轴参考矩形：前3.4、后1.05、半宽1.05 m；局部膨胀1.6、全局3.75 m |
| 几何校验 | point/ideal 校验 | 车体轮廓、曲率、朝向、实际后轴接续校验 |
| 动作分段 | 一条规划路径整体下发；仍有图路线段切换 | 按前进/倒车分段，cusp 停稳再交接 |
| cusp 完成 | 无专门 cusp checker/交接 | 0.2 m、0.35 rad、实测线/角速度≤0.05；随后重新校验接续 |
| 执行反馈 | 运动学 RPC 和状态新鲜度 | Native 遥测/ACK/累计年龄、换向确认、车端租约 |
| 目标接近点 | 前车体长度默认0，仍考虑相机安全距离 | 默认前车体长度3.4 m + clearance；接近点也可能不同 |

## 同一历史姿态的离线对照

输入保留 `nav2_adapter/test/fixtures/physical_short_cusp_join_20261012.json`：短倒车段约1.706 m，三组 Native 姿态起点偏差约0.172 m/8°，采样在下发前后，非精确 Bridge 回调姿态。

新增 `tools/compare_carrier_models_offline.py`，从生产 Lua 读取 XY 积分表达式，构造理想点载体“原地旋转—直线倒车—原地旋转”指令。1.2 m/s、0.8 rad/s、单步≤0.02 s；三组均到达端点与目标朝向，数值位置误差<4e-12 m。

同样的初始姿态/目标，在保留8 m半径的零延迟自行车 endpoint-carrot 反馈下，最接近距离为0.208819、0.210013、0.207305 m，均未进入0.2 m判定范围，随后触发单方向保护。

这只证明空障碍条件下点载体存在允许的到达动作，以及当前有限半径短段反馈失败；点载体动作由诊断构造，未声称原版RPP实际会产生它。未运行Lua引擎、真实C++插件、DDS、障碍检查或完整搜寻。自行车失败也不证明任意合法机动下不可达。

## 主要原因与判断边界

约8°姿态误差在点载体上可原地消除；8 m半径车改变同样角度需要约1.12 m弧长且会改变位置。此为运动尺度估算，不是全局不可达证明。上一段进入完成容差，不能自动保证实际停止姿态可接入下一段。

当前已定位缺口集中在真实模式经过的链路：

1. Smac 成功路径与下游曲率/姿态校验存在不一致反例，尚未明确量化、解析接续、平滑或解释哪一步最早违约。
2. cusp 完成区与下一短段可执行性没有联合保证。收紧接续检查会提前拒绝，却不生成可行新路径。
3. 接续拒绝分支直接重新规划，没有普通失败恢复预算；首次下发前接续失败又进入执行失败归属，未继续尝试其他候选。点载体没有同样的 Ackermann 交接分支。
4. 真车转向机构、制动和换挡会进一步改变实际停止姿态。PAD 转向输入滤波已有 DIRECT 候选及组件证据，机构动态仍在；不得把已修滤波重复当全部当前根因。

主要结论：规划输出、局部跟踪、完成判定和下一段交接的车辆运动契约尚未闭合。理想点载体有额外姿态调整能力，并绕过相关约束/分支，因此可不暴露同一问题。几何反例无需视觉模型即可出现；当前没有证据把它解释为视觉记忆原理失败，完整记忆流程也仍未验收。

独立引擎2～4.8 s共同响应空档/原生崩溃未定位。真实物理可能改变负载，但缺同负载引擎级对照，不能断言物理计算太重或时间戳延迟是所有重规划的根因。此短段在零延迟条件仍失败，说明先处理几何交接有依据。

## 验证与后续

4项新诊断测试通过：原地旋转不改变导航原点、直线/圆弧积分、正反向/零距离目标、三组历史姿态模型区分。结果与8个输入SHA见 `test_artifacts/offline_execution_audit_20261013/carrier_comparison.json`，日志为同目录 `carrier_comparison_tests.log`。上轮生产回调替身/路径校验反例仍见 `audit.json`。

后续真正控制变量应固定同一路径、初始姿态、轮廓、RPP与cusp参数：先保留8 m半径去掉动态/延迟，再加入转向/制动动态，最后真实BeamNG。`ideal_point`仅作为不同能力的参考组。Lua虽然已有ackermann运动学选项，但直接换参数不足以验证整个物理栈；Native健康/ACK/实测停稳接口仍须适配核验，禁止靠关闭健康保护构造成功。

本轮未改生产代码、未连接服务器；测试通过代表诊断有效，不是故障修复或现场成功。必要验收待执行，未commit。
