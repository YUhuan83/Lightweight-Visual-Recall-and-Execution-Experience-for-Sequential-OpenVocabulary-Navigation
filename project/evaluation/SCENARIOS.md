# 统一乡村场景与试验协议

## 状态与边界

这是 BeamNG WildOS 的独立离线设计，不是已导入地图或已完成实验。地图名称、版本、车辆、世界坐标、目标可达性均未确认。不得从旧 Gazebo `assets/evaluation_truth.json` 移植数值，或把示意坐标写成 BeamNG 实测坐标。机器模板必须保持 `draft` 与显式 `null`，安装后勘测、人工驾驶验收、冻结布局和引用记录后才允许申请 `ready`。中文在本目录新文档中用于明确用户所需协议，其余代码/模板使用 ASCII。

## 统一布局

三类任务共用一片连续乡村环境，而非三张互不相关的测试小地图。主干水泥路连接农舍/院落，分支进入有坑洼、车辙、碎石、起伏坡面的粗糙道路，再连接有遮挡、窄通道、树干、灌木、石块和倒木的林缘。每类任务的有效路线都应包含水泥、粗糙路和林缘障碍段；需要人工记录各路段覆盖，不能以材质贴图冒充真实几何或真实土壤物理。

- 水泥到粗糙段无重叠路面、隐藏台阶或掉落缝；坡度、车辙深度和离地间隙根据实际车辆验收，不预设某车型能通过。
- 可通行走廊净宽至少车辆宽度加两侧各 0.5 m 安全裕量，弯道满足实测最小转弯半径；阈值是设计要求，不是已测量结果。
- 树干、倒木、石块具有经检查的碰撞体；草/灌木哪些可穿透必须明确，视觉遮挡与物理碰撞不可混淆。
- 设置外观相近的干扰物及多个候选院落，起点不能直接看到目标；目标不能仅靠实例名被模型识别。
- 目标物坐标与可达停车点分开。可达点须位于合法可驾驶区域，停车半径整个有效区域不得跨围栏/墙体提供“隔墙到达”。必要时减小半径并重新冻结协议。
- 各分支保持至少一条到目标的实测可行路线；死胡同是局部陷阱，不是整个任务无解。纯不可达任务应另订协议，不能混入此处成功率。
- 布局、碰撞网格、出生方向、车辆参考点、世界坐标系和验收轨迹均版本化，禁止测试后为某方法偷偷移动目标或障碍。

## 三类任务

| 家族 | 布局与任务 | 必须验收的失败陷阱 |
|---|---|---|
| `long_range_search` 长距离目标搜索 | 从乡村水泥路出发，经粗糙道路和林缘搜索指定物体；设计最短实测可行路线至少 300 m、直线距离至少 150 m，并记录实际长度；目标被建筑/植被遮挡，有至少两个干扰候选区 | 不能把“先验中心”当精确终点；发现相似物体但身份错误不成功；距离长不等于视觉难度充分 |
| `fence_approach` 围栏接近 | 可从一侧看见围栏后的目标；必须发现偏离直线路径的开放入口，绕行并在目标同侧合法停车区驻留；入口不在出生可视区域 | 禁止在围栏外仅凭距物体近或识别正确判成功；入口净宽/转弯、围栏碰撞连续性、停车区与半径必须实驾确认 |
| `dead_end` 死胡同恢复 | 林缘/农舍支路形成诱人的局部前进方向，尽头由墙体、围栏或倒木封闭；另一分支通向目标，设置可退出或倒车恢复的空间 | 禁止靠穿模、传送或人工救援继续当自主成功；记录进入、回退和重新选路的传感器/轨迹证据，不把碰巧没进死路称作恢复成功 |

目标类别（模板中的桶、水箱、拖车）是待资产/视觉验收的候选，不是模型已能识别的保证。长距离阈值是设计目标，地图无法满足应修改并冻结新协议，不捏造满足记录。围栏和死胡同任务也包含长距离接近段，但主要诊断分别是绕行和退出局部陷阱。当前通用评估器只给终局与基本指标，围栏穿越是否合法、是否实际进入死路、恢复耗时需额外标注/回放，尚不自动计算。

## 语义先验与基线

允许的近似先验是独立于本回合 GT 的粗粒度区域/描述，例如“林缘农舍附近”。来源可为冻结的旧粗地图或统一人工提示；须记录来源、区域中心/半径及版本。先验应覆盖多个可达候选区，不包含可达停车点、围栏入口、隐藏连通图或目标精确位置。不得读取当前 GT 后生成以真实目标为中心的小圆，也不得只给被评测方法一个特别准确的提示。先验文本/区域在试验前冻结，不能随算法表现修订。

搜索算法输入包含传感器、自然语言目标、可选粗先验及声明的 `localization_mode` 允许的自车里程计。`oracle_pose` 只允许自车真值位姿及可选自车线/角速度转换为局部里程计；`estimated_pose` 使用 LIO，禁止 oracle 输出、真值初始化及真值纠偏。两模式均禁止向搜索算法提供 GT 目标/可达点、评分距离、隐藏身份标签、正确身份审核结论、全地图或隐藏障碍连通图/语义；正常传感器观测及算法自行建图不属于隐藏地图。不向算法发布或挂载整份 scenario/log。模板含评分字段，**不是算法输入配置**。日志中的算法证据需结合独立传感器帧审核；仿真对象 ID 只可用于离线核验。

`input_contract=sensors_only/sensors_approximate_prior` 描述上述传感器加允许自车定位、无/有粗先验的条件，不代替必填定位模式。oracle 是理想定位实验性上界，不是完整复现，也不保证更好成绩。两阶段永不池化；只可固定其他条件与 trial/seed 作为受控消融分别报告。评分世界 GT 来源和成功判据不变。离线评估只能校验元数据/来源声明，不能验证物理来源或阻止将真值谎报为 LIO，实际隔离须独立审计。

| 建议标签 | 模式/输入 | 对照范围 |
|---|---|---|
| `wildos` | object_search，sensors_only 或 sensors_approximate_prior，显式声明定位模式 | 开放词汇搜索；oracle 条件不是完整复现 |
| `frontier_semantic` | 与 WildOS 相同输入，几何前沿探索加相同语义检测/停止模块 | 对比探索策略，固定感知与底层控制 |
| `wildos_no_prior` | object_search，sensors_only | 先验消融，独立输入分组；不得与有先验组混成相同协议均值 |
| `point_goal_nav` | point_goal，sensors_exact_point_goal | 显式获得可达停车点，仅诊断定位/规划/控制；不是物体搜索基线成绩 |

这些是建议实验条件，不表示已实现算法。点目标不需要语义命中，搜索必须有语义身份加可达距离与驻留，因此两者无论名字如何都不能同榜排名。碰撞/干预政策、预算、传感器、控制频率或先验不同亦不得混比。

## 试验协议

1. 安装后先人工勘测与遥控通过全部路段，确认车辆碰撞、围栏入口、退出空间、目标可见性、语义候选与可达停车区；保存验收记录并补全 null。评分模板校验通过不代表实际验收通过。
2. 正式测试前冻结协议：建议每家族至少 5 个布局/出生变体、每变体 5 个预注册种子，各方法严格配对。种子控制出生、干扰物/天气等允许变化；冻结方法执行顺序随机化。试运行调参使用独立种子，不能选取成功试次作为正式样本。
3. 建议初始预算 900 仿真秒、成功半径 2 m、驻留 3 s、评分采样间隔上限 0.1 s、距离核对容差 0.001 m。车辆/围栏几何不允许 2 m 时缩小半径，在正式试验前版本化。禁止根据某次结果调阈值。人工干预建议 disqualify；碰撞可 report_only 同时公开次数，安全实验另设 disqualify 分组。
4. 每回合重新初始化算法地图/记忆、车辆损伤与场景状态，记录运行/回合/试验 ID、种子、全部 profile/revision。跨回合预训练/缓存内容须统一并写入算法版本，禁止某方法继承隐藏目标记忆。
5. 从同一启动屏障开始回合相对 sim_time=0，位置/距离/证据/事件同步记录，暂停不重复写相同仿真时间。丢帧超过上限、重置、传送、记录器断流应终止并登记无效采集，不能拼接前后记录。
6. 满足停止条件即结束；到预算未成功记 failure/timeout，安全中止记 failure 及原因。原因未知且完整记录可记 unknown/null，不计成功。日志被截断必须 complete=false，评估器拒绝；另记基础设施故障，预注册重试规则且公开所有失败采集。
7. 用独立评分端核实语义身份、事件完整性及目标可达性。重复接触每次分离再接触计新 collision ID；接管持续过程用同 ID。未知事件数不能用空列表伪装零。
8. 按家族、布局、输入协议、定位模式、环境、车辆等分组报告所有有效回合，公开 unknown、无效采集和重试数。oracle 与 estimated 分组不得合并。配对种子一致后再比较方法，不把 point-goal 的高成功率当作 WildOS 搜索上界证明。保存失败回放，用于区分感知、可通行性、探索、控制和基础设施问题。

当前没有真实通过率、路程、碰撞统计或运行时间。单元测试输出只证明离线校验/计算代码对合成输入的行为。
