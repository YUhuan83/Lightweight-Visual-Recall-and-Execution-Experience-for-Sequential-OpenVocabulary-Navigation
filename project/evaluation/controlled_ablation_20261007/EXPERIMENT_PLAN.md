# WildOS 与视觉记忆的控制变量实验

日期：2026-10-07。当前阶段：离线设计与版本盘点，尚未建立实验提交或运行仿真。

## 要回答的问题

1. 固定规划和执行链后，新增视觉记忆能否缩短同地图、同进程的第二目标搜寻？
2. 相同路径和指令经过 BeamNG 时，执行是否稳定？
3. 新增 heading 机制是否单独改变路径跟踪、目标切换或搜寻效率？

这三个问题分别测量，避免用整套系统之间的差异推断单一模块的因果作用。

## 实验分组

| 组别 | 算法 | 共同执行框架 | 用途 |
|---|---|---|---|
| R | 经上游提交核验的 WildOS 原版核心 | 同一套 BeamNG 适配、建图输入、Nav2 和到达判据 | 原文复现与当前系统的整体比较 |
| A | 当前共同算法核心，关闭全部新增记忆，固定 heading 机制 | 与 B 完全相同 | 视觉记忆的直接对照组 |
| B | A 加同进程被动视觉记忆和候选检索 | 与 A 完全相同 | 主实验：只改变记忆机制 |
| C | B 加新增 heading 决策机制 | 与 B 完全相同 | 独立评价 heading 的作用 |

R 与 B 的差异可能包含多项算法改动，因此不能直接将差异全部归因于视觉记忆。A/B 是记忆的因果对照；B/C 是 heading 的对照。无需一开始运行所有组合，先完成执行验证和 A/B。

只设置 visual_memory_enabled=false 不足以构成 A：还需盘点 visual_memory_map、semantic_landmarks、object_goal_memory、recent_scene_features、记忆 heading bonus、执行反馈学习及查询切换后的历史候选发布。哪些属于实验自变量，必须在运行前写清楚。保留 WildOS 原有空间导航图，它本身就是基线能力。

## Git 管理方式

建议在专门的实验仓库中按以下顺序建立提交，避免改动当前工作区的索引、混入录像和密钥：

1. 导入经核验的论文源码，记录上游 URL、commit、模型权重摘要与许可证。
2. 建立共同的 BeamNG 运行框架提交，包含双方必须使用的接口修复。算法性改动逐项登记，不以“适配”为名隐藏。
3. 建立 A 提交，在共同框架上明确关闭新增记忆，固定 heading 状态。
4. 建立 B 提交，diff 仅包含预先声明的视觉记忆模块及其必要接口。
5. 如需研究 heading，建立 C 提交，diff 只包含该机制。
6. 对各提交建立独立 worktree，并使用独立 ROS 构建和安装目录。打标签后实验期间不改代码。

标签可采用 experiment/wildos-reference、experiment/memory-off、experiment/memory-on、experiment/memory-heading。这里是命名建议，尚未创建这些标签或分支。

每轮记录 Git commit、工作区是否干净、配置摘要、模型权重摘要、Lua 文件摘要，以及实际运行模块和安装 YAML 的路径与摘要。不能仅记录工作树版本；服务器必须证明加载的是该版本。

## 所有组共同固定的条件

- BeamNG 版本、East Coast USA 地图版本、Town 加油站出生位置和朝向。
- 载体统一使用 ideal_point；相机和 LiDAR 安装位置、频率、量程与分辨率一致。
- 共同使用同一份正确转向约定、导航参考点补偿、TF 和时间映射实现。
- GraphNav、Nav2 全局规划器、RPP、速度设定、角速度约束、路径取消和恢复参数一致。
- 障碍层、碰撞设置、随机种子、天气、交通、主机及推理资源配置一致。
- 检测模型、权重、文本查询、到达判据、超时及录像配置一致。
- 每个 trial 开始时地图和搜索状态相同，新增记忆为空。trial 内地图只加载一次、vision 进程保持运行；trial 间清空状态，防止前一组向后一组泄漏记忆。
- 保持相同环境和资源分配；记录实际处理延迟。记忆引入的算力开销属于实验结果，不能把它人为排除。

即使使用相同种子，闭环仿真的传感器与调度也不一定逐帧一致；“相同条件”指配对初始条件和运行约定。需要逐帧相同输入时采用录制数据回放。

## 分层实验顺序

### 第一层：共同执行链资格验证

绕过模型、记忆和 frontier 选择，给共同执行链相同的直线、左弯、右弯和原地旋转任务。检验正负角速度方向、导航原点纯旋转漂移、路径横向误差、沿路径进度、停驶和 action 取消。

若这里失败，先将问题归入共同执行链；此时 A/B 搜寻结果不能有效评价视觉记忆。资格阈值和路径应在试验前固定，不能为了让 B 通过而单独调整。

### 第二层：相同历史观测下的记忆检索

使用已有的带时间戳 RGB、LiDAR、TF/odom 观测流，在同一历史输入条件下检查 B 是否形成有效空间记忆、查询切换后是否产出可达候选。记录候选位置、历史观察位置、证据、检索耗时和容量。

这项回放可以检查逻辑和接口；固定录像无法生成算法采取不同动作后应看到的新画面，因此不能代替闭环成功率。

### 第三层：完整 A/B 闭环

每轮在 Town 加油站开始，第一查询为 green residential house；达到预先规定的真实确认和到达条件后，再查询 gas station。不预先下达记住加油站的命令，不要求离站 20 米或沿原路返回。

第一目标失败时，记录整轮失败并注明第二阶段未运行。不能把这种试验记成记忆重访失败，也不能只报告进入第二阶段的成功试验。

为更清楚评价记忆本身，可补充配对试验：双方在同一段独立记录的有效历史观测后，从同一位置接收 gas station 查询。该项与自然搜寻整轮结果分别报告，不注入目标坐标作为“视觉记忆”。

## 指标与统计

- 主要指标：完整双目标成功率、第二目标真实到达用时、第二阶段路程。
- 分开报告第一目标成功率，以及进入第二阶段后的条件成功率。
- 执行指标：横向误差、沿路径进度、非预期停驶时长、转向指令/实测航向响应、FollowPath 取消与重规划次数及原因。
- 记忆指标：有效历史记录数、候选检索命中、可达候选比例、新鲜视觉确认、检索和候选规划耗时、CPU/GPU/内存占用。
- 先做少量配对预试验估计方差，再确定正式样本量；单轮录像不能用于性能结论。
- A/B 使用相同种子配对，交替或随机运行顺序，避免运行顺序和服务器负载偏向某一组。
- 报告配对差异与置信区间，并保留超时、失败和无候选记录。基础设施失效的作废条件在运行前定义，并同时报告作废数量。

## 结论如何解释

| 结果 | 支持的解释 |
|---|---|
| 固定路径也失败，A/B 都不稳定 | 共同执行/接口是首要阻塞项 |
| A 稳定，B 不稳定，且 B 无记忆候选介入 | 排查被动采集开销、frontier 评分或额外回调，而不是候选导航 |
| A 稳定，B 仅在记忆目标介入后失败 | 排查候选坐标、观察朝向、可达性及状态切换 |
| A/B 执行都稳定，B 第二目标更快到达 | 支持记忆带来实际搜寻收益 |
| B 稳定，C 明显恶化 | 将问题定位到新增 heading 机制 |
| B 命中历史目标但没有加速 | 检查候选评价开销、冗余旋转和再次确认成本 |

当前仍只有离线条件。本文没有生成 A/B 性能结果，也没有声称论文基线已完成复现。
